## protocol/ — FROZEN (P1)

- **messages.ts**: discriminated unions on `type`.
  - Main→worker: `init{seed, gravity, snapshotHz (default 120), debugStrains, capacity?}`, `ground{mode:'plane', y, materialId}` (`mode:'heightfield'` superseded by P3 `groundHeightfield`, see Terrain protocol), `spawn{objectId, rig: RigDef, transform{pos, quat[x,y,z,w]}}`, `despawn`, `input{objectId, actions: Partial<ActionState>}` (merge), `reset{objectId, transform}` (full repair), `timescale{value}`, `returnBuffer{buffer}` (transferred). Reserved: `setBubble`, `keyframeRequest`, `replaySeek`.
  - Worker→main: `ready`, `snapshot{buffer}` (transferred), `fatal{message, stack?}`, `unimplemented{command}` (reserved commands/variants), `error{command, message, objectId?}` (recoverable rejection).
  - Commands apply in arrival order at the next step boundary.
- **Snapshot capacity** is fixed at `init` (`DEFAULT_CAPACITY` 64 objects / 32768 nodes / 131072 beams); spawns beyond it get `error`.
- **layout.ts**: `[header 128 B][objects][impacts][beamBreaks][skids][nodes][strains?]`, every section 16-byte aligned; all offsets are exported consts and also stored in the header. Magic `'CRMP'` (u32 0x504D5243), `SNAPSHOT_VERSION` 1. Object record 160 B: id, flags (bit0 sleeping), nodeOffset, nodeCount, beamOffset, beamCount (element indices), 2 reserved words, 32 f32 telemetry (zeros in P1; all 32 slots assigned in P2, see Vehicle telemetry). Nodes f32 xyz × nodeTotal. Strains (only with header flag bit0) f32 × beamTotal = signed force/breakF in [-1, 1], tension positive, NaN broken.
- **events.ts**: impact{objectId, materialId, pos, normal, impulse} cap 256; beamBreak{objectId, beamIndex (OBJECT-LOCAL), pos} cap 256; skid{objectId, materialId, pos, slip m/s, load N} cap 512. Discovery order; drops beyond capacity counted in per-kind header overflow. Events accumulate across skipped snapshots.
- **codec.ts**: `SnapshotWriter` / `SnapshotReader` (views created on `attach`, everything else allocation-free; reader subarrays lazy + cached per attach), `checkSnapshot`, `SnapshotFormatError`, `BufferPool`.
- **Buffer pool**: 3 buffers allocated by the worker at init. Worker acquires one per snapshot, transfers it; if none is free it skips the snapshot (never blocks). Main keeps ≤ 2 (previous + current for interpolation) and returns the older via `returnBuffer` as soon as a newer one arrives.

## ActionState — FROZEN (P1)

`throttle`=0 (0..1), `brake`=1 (0..1), `steer`=2 (-1 left..1 right), `handbrake`=3 (0..1), `clutch`=4 (0 engaged..1 disengaged), `gearSelect`=5 (integer: -1 R, 0 N, 1..n). Indices (`Action`) address the worker's per-object Float64Array and the replay input log. **P8 additive:** `horn`=6 (0..1, optional field; see "P8 horn").

## MaterialId — FROZEN (P1)

0 asphalt, 1 grass, 2 dirt, 3 rock, 4 gravel, 5 concrete, 6 metal. Defined in `src/protocol/messages.ts`, re-exported by `src/sim/types.ts`. Contact μ = node friction × material friction.

## HeightSampler — FROZEN (P1)

`src/sim/types.ts`: `heightAt(x,z)`, `normalAt(x,z,out: Float64Array)` (unit, C0-continuous smoothed, writes out[0..2]), `materialAt(x,z)`. Deterministic, allocation-free. Plane in P1, heightfield in P3.

## RigDef / CompiledRig — FROZEN (P1)

`src/sim/rig/types.ts`. RigDef is plain JSON: `name`, `nodes[{id, pos, mass, friction?, radius?, group?, collidable?}]` (**mass ≤ 0 = pinned**, invMass 0), `beams[{a, b, type: normal|bounded|support|hydro|shock, k?, d?, deform?, breakF?, boundsLow?, boundsHigh?, preload?, hydroTravel?}]`, `groupDefaults?`. Defaults in `RIG_DEFAULTS` (k 9e6, d 12e3, deform 4e5, breakF 1e6; deform/breakF ≤ 0 = never → Infinity when compiled). CompiledRig = resolved typed arrays in declaration order. `StabilityReport`, `RigStats` types live there too. Sim-side SoA arena (`SimState`), `SimObject`, `EventSink`, `BeamType` and kernel signatures are frozen in `src/sim/types.ts` (worker-internal).

## Canonical ordering — FROZEN (P1)

Nodes and beams in RigDef declaration order everywhere (arena, snapshots, GPU bindings; never sorted/compacted, broken beams stay with active 0). Objects by ascending objectId (stepping, arena allocation, snapshots). Fixed per-step phase order: commands → per object: beams → ground contacts → other forces → integrate (P2 amendment: vehicle pre-step and steering hydros run before beams, see VehicleDef; P4 amendment: static-collider contacts run after ground contacts, as the last force pass). Events in discovery order. Cross-object contact pairs sorted (lower object id, then node index). Full text in `src/sim/types.ts`.

## VehicleDef / CompiledVehicle — FROZEN (P2)

`src/sim/vehicle/types.ts` (full spec in its doc comments).
- **Vehicle frame** (rig-local): up +Y, **forward −Z**, right +X. Wheel ω > 0 = rolling forward (spin axis = vehicle left). steer +1 = right.
- **VehicleDef** (plain JSON): `name`, `body: RigDef`, `wheels: WheelDef[]`, `drivetrain: DrivetrainDef`, `brakes{frontBias, handbrakeTorqueMax}`, `aero{dragCoeffArea, liftCoeffArea}`, `steering{maxWheelAngleDeg}`, `frame{origin, front, top}` (body node ids).
- **WheelDef**: `id`, `hubInner`/`hubOuter` (positions; hubs are ALWAYS generated; outer = outboard), `axle: front|rear`, `radius`, `rimRadius`, `width`, `rays` (even, 10–14), `tireRingSpring/Damp`, `rimSpring/Damp`, `sidewallSpring/Damp`, `hubMass/rimMass/tireMass` (wheel totals), `friction` (≈2.0), `steered`, `driven`, `braked`, `brakeTorqueMax`, `handbrake`, `attach: string[]` (body node ids; emits hubI–id, hubO–id per id), optional `tireNodeRadius`, `attachSpring/Damp/BreakF` (`WHEEL_DEFAULTS`).
- **Wheel node ids**: `${id}.hubI`, `${id}.hubO`, `${id}.rimI{k}`, `${id}.rimO{k}`, `${id}.tireI{k}`, `${id}.tireO{k}`, k = 0..rays−1 (`wheelNodeId()`). Body beams may reference them (suspension arms to hubs, steering hydros to knuckles).
- **Canonical merged order**: nodes = body nodes, then per wheel (declaration order) hubI, hubO, rimI[0..n), rimO[0..n), tireI[0..n), tireO[0..n) (2+4n). Beams = body beams, then per wheel: attach beams, axle hubI–hubO, then 22 beams per ray (8 rim, 4 tread, 8 sidewall, 2 X-brace) in the order documented at `WHEEL_BEAMS_PER_RAY`. **Amended (P2 handling):** every rim/tread quad is X-braced with two half-stiffness diagonals (`rimI{k}–rimO{k1}½ … rimO{k}–rimI{k1}½`, same for the tread); one-way diagonals made each wheel chiral, and since left/right rings are parameterized in opposite rotational senses both wheels of an axle crabbed the same way under torque (the sedan spun out on a straight launch). 4-wheel cars declare wheels FL, FR, RL, RR.
- **Steering**: every `hydro` beam in `body` is a steering hydro driven by the `steer` action (P1 engine hydro pass, unchanged).
- **DrivetrainDef**: `torqueCurve [rpm, Nm][]` (→ LUT, `TORQUE_LUT_STEP_RPM` 50, lerp), `idleRpm`, `redlineRpm`, `revLimitRpm`, `engineInertia`, `engineBrakeTorque`, `gearRatios` (forward), `reverseRatio` (magnitude), `finalDrive`, `shiftTimeS`, `autoShiftUpRpm`, `autoShiftDownRpm`, `diff open|locked|limited` (one diff across all driven wheels), `diffLockTorque?`, `clutchMaxTorque`, `transmission? auto|manual`.
- **Brakes**: per wheel `brakeTorqueMax · bias_axle / max(frontBias, 1−frontBias)`; handbrake `handbrake·handbrakeTorqueMax`; wheel gets the max.
- **CompiledVehicle**: merged `CompiledRig` (after MINIMASS at ω·dt 0.35), `bodyNodeCount/bodyBeamCount`, `CompiledWheel[]` (rig-local node/beam ranges, `spinSign`, `corner`, `tireRingRadius`, `hubLinkBeams`, biased brake torques), `CompiledDrivetrain` (`torqueLut`, `gearRatioTable` indexed gear+1 = [−rev, 0, r1..rn], `drivenWheels`), `frameNodes`, `totalMass`, `massDriftPct`. Builder signatures: `BuildWheelRig`, `BuildVehicleRig`, `CompileVehicle`, `ValidateVehicle` (beam budget 3500 player / 1500 traffic).
- **Per-tick order (amends canonical rule 3)**, per object ascending: vehicle pre-step [estimate ω all wheels → `stepDrivetrain` → `applyWheelTorques` per wheel → parking clamp → aero] → steering hydros → beams → ground → integrate. Positions are unchanged between pre-step and ground pass, so ground normal force evaluated in the pre-step (`groundNormalForce`, an additive export of `collision/ground.ts` with identical math) equals this tick's contact force.
- **ω estimate** (amended P2): INERTIA-WEIGHTED over the rim AND tyre rings, `ω = Σ m_i (v_i − v_hubMid)·(s × ρ_i) / Σ m_i |ρ_i|²` (= L_axle / I_axle), ρ = radial offset from the axle. A rim-only estimate is non-collocated with the tyre-ring torque and pumped the rim–tyre torsional mode under the brake ramp. **Slip ratio** (`WheelRuntime.slipRatio`) uses the effective rolling radius `WheelRuntime.rollRadius` = load-weighted axle → in-contact tyre-node-centre distance along the ground normal (unloaded radius when airborne); the unloaded radius read +0.09 on a free-rolling wheel.
- **Torque law**: τ = drive + brake about s; each of the N = 2·rays tire nodes gets `τ/(N·r)·t̂_i` (r = `tireRingRadius`); hubI and hubO each get `−ΣF/2` (zero net force). Brake: `−brakeTorque·clamp(ω/1 rad/s, −1, 1)` (low-speed ramp, no chatter). No body reaction couple in P2. Detached wheel (all `hubLinkBeams` broken): drive torque 0.
- **Parking clamp** (amended P2): engaged when the horizontal COM speed < 0.3 m/s and brake/handbrake ≥ 0.1 on a wheel that has that brake. Per engaged wheel: (1) **brake-pad hold** — a stiction spring on the wheel angle accumulated since engagement, `τ = −0.02·(I/dt²)·θ`, with service + hold torque capped at the wheel's available brake torque (θ re-based at the cap: slips, no wind-up); (2) per in-contact tyre node, the viscous term `0.25·m/dt·v_t` plus a **contact anchor** spring `0.05·m/dt²` toward the touchdown point, together capped at `μN·(1 − tanhR(|v_t|/0.3))` (anchor dragged at the cap, re-armed if > 5 cm away). Capped forces/torques only, never a position constraint.

## P2 handling amendments (additive; handling harness `src/sim/vehicle/handling.ts`)

Measured by `src/sim/vehicle/handling.test.ts` (`node tools/handling-report.mjs` prints the table).

- **Ground friction law** (`collision/ground.ts`): implicit (backward-Euler) Coulomb. The ground pass is the last force pass before integration; per node, `F_req = −(m·v_t/dt + F_t)` (F_t = tangential part of the accumulated force + m·g) is applied clamped to the cone `μ·N`. Inside the cone the node sticks, outside it slides along F_req. The P1 `μ·tanh(v/0.3)` with a `0.5·m/dt·|v_t|` cap needed ~4 m/s of sliding to carry 2 kN on a tread node (the launch wheelspin). `ApplyGroundContacts` takes optional trailing `gx, gy, gz` (gravity, for the tangential part of m·g); the engine passes them.
- **Soft-layer contact** (`RigNodeDef.contactSpring?` N/m, `RigGroupDefaults.contactSpring`, `CompiledRig.nodeContactK`, `SimState.contactK`): > 0 selects penalty stiffness `min(contactSpring, 0.2·m/dt²)`, with damping `2·0.08·sqrt(k·m)·min(1, depth/radius)` (zero at touchdown). 0 keeps the rigid-contact law. `groundNormalForce` reproduces both laws.
- **Tread nodes** (`RigNodeDef.tread?`, `RIG_NODE_FLAG_TREAD` = `NODE_FLAG_TREAD` = 1<<2; `SimState.treadAxX/Y/Z`, `treadF`): the ground stick's cone on a tread node is `sqrt((μN)² − treadF²)`. The vehicle's lateral tread brush writes `treadF` (its force on the node) every tick, before the ground pass.
- **WheelDef** (optional): `tireContactSpring` (tread nodes' contactSpring), `rollingResistance` (C_rr; torque `−C_rr·load·rollRadius·clamp(ω/ROLL_RES_OMEGA_EPS)`, `ROLL_RES_OMEGA_EPS` = 0.1 rad/s so it is Coulomb-like for a parked car), `treadBrushStiffness` / `treadBrushDamping` (> 0 marks the tyre nodes `tread` and enables the brush), `rimHoopTension` / `treadHoopTension` (0..1, hoop tension below). `WHEEL_DEFAULTS` are all 0 (P1 behaviour). `WHEEL_TUNING_205_55R16` uses them (see its doc: C_rr 0.008, rim hoop 1, tread hoop 0.5, tireMass 9.4, μ 1.1). `CompiledWheel` adds `rollingResistance`, `brushK`, `brushC`, `rimHoop` / `treadHoop` (fraction ÷ 2·sin(π/rays)) and `attachNodes` (rig-local attach node indices). `WheelRuntime` adds `rollRadius`, `treadLoad`, `treadNormal`, `treadBrush` and `attachNodes` (global).
- **Tread brush** (`wheels.ts applyTreadBrush`, lateral only), per in-contact tread node:
  - `u = v_hub·â` (â = axle in the ground plane), `δ += u·dt` (reset off-ground), `F = −k·δ − c·u`.
  - F is capped at `μN·(|u|+0.5)/(|(u, u_x)|+0.5)`, the lateral share of the rigid-wheel slip velocity (combined slip); `u_x = max(0, |slipRatio| − 0.12)·|v|` (a locked or spinning wheel; normal drive/brake slip keeps the full lateral share).
  - The contact wrench goes on the rigid wheel: net force half to each hub; the overturning moment as a lateral force pair between `attachNodes` (upright top) and the hubs (the ball-joint path); the aligning moment as a hub couple.
  - Each tread node also gets a lateral damper `0.1·m/dt` relative to the hub.
  - Why: node stick through the carcass gave ~130 N/deg cornering stiffness, capped by the ω·dt budget.
- **Vehicle MINIMASS**: tread nodes (group `wheelTire`) are raised only to `TREAD_OMEGA_DT_LIMIT` = 0.49; everything else stays at 0.35. `validateVehicle.stability` judges per group.
- **Rolling radius / slip ratio**: `WheelRuntime.rollRadius` = mean chord between consecutive in-contact tread nodes × rays / 2π (whole-ring perimeter / 2π when there is no contact pair), low-passed with τ = 50 ms. `slipRatio = (ω·rollRadius − v_x)/max(|v_x|, 0.5)`; the unloaded radius read +0.09 when free rolling.
- **Traction control**: `DrivetrainDef.tractionControl?` (target driven-wheel slip ratio, 0 = off) → `CompiledDrivetrain.tcSlip`. Throttle is cut by `0.5`/(m/s) of excess of the fastest driven wheel over the undriven wheels' mean × (1 + tcSlip). The denominator is floored at 5 m/s, there is no cut below 2.5 × idle rpm (the clutch slips instead), and attack/release are 20/150 ms.
- **Hoop tension** (`wheels.ts applyHoopTension`): each rim / tread ring segment gets tension `T = f·m·ω̂²·r/(2·sin(π/rays))` (m = mean endpoint mass, r = rimRadius / tireRingRadius, ω̂ = min(|ω|, `HOOP_OMEGA_MAX` = 220 rad/s)), whose resultant on the regular polygon is `f·m·ω²·r` toward the axle. Internal forces only (no net wheel force or torque; a flat contact patch gets none). Why: the budget-limited spokes and sidewalls let the rim balloon ~7 cm and the tread ~5 cm at 200 km/h (car 7.5 cm higher), and above ~205 km/h the tread fell into a standing-wave state (rolling radius −10 %, free fronts −4 % → +5 % slip) that drove a ±0.1 rad/s yaw limit cycle. Its geometric stiffness adds `√f·ω̂/(√2·sin(π/rays))·dt` to ω·dt in quadrature (sedan at the cap: tread 0.451 → 0.498, rim 0.347 → 0.459; wheels.test.ts).
- **Per-tick vehicle pre-step** (amends the order above): estimate ω, then `stepDrivetrain`, then per wheel `applyWheelTorques` (+ rolling resistance), `applyTreadBrush` and `applyHoopTension`, then the parking clamp (its node anchor/viscous part is skipped on brush wheels; the pad hold remains), then aero.
- **Sedan chassis** (`defs/sedan.ts`, not a contract but the harness reference): per axle the lower-arm pivots and the tie-rod / toe-link pivot of both sides form a rigid subframe of fixed `K_SUBFRAME` beams (pivot masses fixed outside the CG solve, sized for the beams); the link pivots sit `LINK_REACH` = 0.35 m fore/aft of the hub; rear hub links ×2 (`REAR_LINK_FACTOR`). Engine 350 N·m flat 3500–6500 rpm (238 kW), auto upshift 6900 rpm, TC 0.14.
- **Top-speed check** (`handling.ts runTopSpeed`): full throttle at 200 / 210 km/h held in the gear with the most wheel force (manual box) must accelerate, plus a 10 s full-throttle straight from 195 km/h (must pass 200 km/h without weave). A full run from rest is > 60 s of sim.

## WorldLayout — FROZEN (P3)

`src/world/types.ts` (full rules in doc comments); the map itself is `DEFAULT_LAYOUT` in `src/world/layout.ts` (data, hand-designed control points, ASCII sketch in its header; `WORLD_LAYOUTS` registry by id).
- Coordinates: metres, Y up, map square of `size` centred on the origin, north = −Z. Yaw about +Y, 0 faces −Z (vehicle frame). Rotations in layout data are unit direction vectors, never angles.
- `WorldLayout{id, name, version, seed, size, terrain: TerrainParams, waterLevel, zones, pads, roads, junctions, spawnPoints, colliders (P5), props (P5)}`. Bump `version` on any change that alters generated terrain.
- **Zones** (`ZoneShape` circle/ellipse/rect/polygon + soft `blend` → smoothstep mask) apply in a fixed kind order: plains (fbm) → hills (fbm + lift) → mountains (MAX over `MountainPeak` bumps `height·(1−u²)²`, plus ridged detail scaled by mask × macro/peak) → lake (`waterLevel − depth·(1−r²)`, dry shore ≥ waterLevel + shoreLift in the blend band) → town/arena flatten. Then edge rise, `pads` (flatten, height null = mean), roads, clamp, paint.
- **Roads** `RoadDef{id, name, kind: highway|country|mountain|dirt|street|arena, closed, points: [x, y|null, z][], width, lanes (per direction), shoulder, bank? (max cross-slope), material, markings: highway|center|edge|none}`. y null = follow pre-road terrain (disc average). Centreline = `core/spline` centripetal Catmull-Rom. Per-kind tuning in `ROAD_KIND_DEFAULTS` (priority dirt < street < country < mountain < arena < highway, smoothRadius, maxGrade, bankFullRadius, blend, surface ribbon|splat). Carving: verge-level cross-section `y + bank·clamp(d, ±w/2)` out to the shoulder edge, smoothstep blend back to terrain; higher priority carves last. Bank sign: + = right side higher; κ + = turning right; right vector `(−tz, 0, tx)`.
- **Junctions** `{id, pos, roads[]}`: every listed road passes within 1 m of pos. Roads resolve by priority DESC; a road meeting a resolved one has its y eased to that road's surface over `JUNCTION_EASE_M` (40 m). Roads meet ONLY at junctions (overpass-free; A tests no other centreline approach).
- **Spawns**: on-road `{road: {id, s, d, reverse?}}` or free `{pos, yaw}`, resolved into `TerrainData.spawns`.
- P5 placeholders: `PadDef`, `PropPlacement`. (`ColliderDef` was a placeholder here; P4 replaced it, see "Static colliders". `version` also bumps on collider changes.)

## TerrainData — FROZEN (P3)

`src/world/types.ts`. `generateTerrain(layout): TerrainData` is PURE and deterministic (seeded `core/rng`/`core/noise` only; only `+ − × ÷ sqrt floor abs min max` and simplex-noise; fixed iteration order) and validates the layout.
- Grid: sample (col, row) at `x = originX + col·spacing`, `z = originZ + row·spacing`; row-major `row·cols + col`; `cols = rows = size/spacing + 1`. Default 1408 m @ 1 m → 1409² ≈ 1.99 M samples, 22 × 22 chunks of `TERRAIN_CHUNK_CELLS` = 64.
- `heights` Float32Array (7.9 MB); `splat` Uint8Array ×4 (7.9 MB): **R paved, G dirt, B rock, A gravel, grass = 255 − (R+G+B+A)** (sum ≤ 255 guaranteed: 5 sets in one RGBA8 texture, exact partition of unity under filtering; concrete = paved set tinted via the material map); `material` Uint8Array MaterialId per sample (2 MB, nearest lookup). ≈ 18 MB per side.
- Also `layoutId, layoutVersion, seed, minHeight, maxHeight, waterLevel`, `roads: RoadProfile[]` (layout order) and `spawns: ResolvedSpawn[]`, `hash` = `hashTerrain()` (FNV-1a 32 word-wise over dims, heights, material, splat, road stations).
- **RoadProfile** = resolved road: stations every `ROAD_STATION_SPACING` 2 m, `ROAD_STATION_STRIDE` 7 f64 `[x, y, z, tx, tz, bank, curvature]` (`RoadStation` offsets), `length`, `stationCount`, width/lanes/shoulder/material/markings/surface. Ribbons, AI and spawns consume profiles, never re-derive from RoadDef. Helpers `sampleRoad(profile, s, out)` (linear between stations, wraps closed) and `projectToRoad(profile, x, z, out, hintS?)` → `{s, d, dist, y}`; allocation-free.
- **TerrainSampler** (`createTerrainSampler(terrain)`, `src/world/sampler.ts`) is structurally identical to sim's FROZEN `HeightSampler` plus `splatAt`/`contains`: bilinear `heightAt`; `normalAt` = bilinear blend of central-difference vertex normals, renormalized (C0-continuous); `materialAt` nearest; edge-clamped outside the grid; allocation-free, sim numerics. The same object drives collision, cameras and ribbon conforming.

## Terrain protocol — FROZEN (P3, additive to protocol)

- Main→worker `groundHeightfield{layout: WorldLayout, terrainHash}`: the worker regenerates terrain itself (KB of JSON instead of 18 MB of arrays; collision == visual by construction), compares `hashTerrain` with `terrainHash` (0 = skip), installs its own terrain either way, and answers worker→main `terrainReady{layoutId, terrainHash, matched, generateMs}`; a mismatch also posts `error`. Send before spawning (spawns queued behind it apply after). The P1 `ground{mode:'plane'}` is unchanged; the reserved `ground{mode:'heightfield'}` variant stays `unimplemented` (superseded).
- **Game boot (P3, `src/main.ts`):** `groundHeightfield` is the worker's FIRST ground command (never a plane first: switching ground types de-inlines the sampler). Main sends `terrainHash` 0 so the worker's generation overlaps main's (main's render copy is generated in a helper worker, `src/app/terrainWorker.ts`, arrays transferred), then compares `terrainReady.terrainHash` with its own hash and logs an error on mismatch. Vehicles spawn only after `terrainReady`.

## Render API — FROZEN (P3)

### Render budget amendments (perf pass, additive)
- **Post:** `RenderPass → N8AOPostPass → [SanitizePass] → EffectPass(...)`. The sanitize pass (whenever bloom is on) replaces non-finite texels (IEEE exponent bits all ones, plus `isnan/isinf`) with black and clamps to `SANITIZE_MAX` (1024, scene-linear) BEFORE bloom reads the buffer: one NaN/Inf pixel from a sun glint otherwise turned the whole frame black through bloom's mip blur (e2e `lighting.spec.ts` checks guarded vs unguarded). n8ao `transparencyAware` is off and its per-frame auto-detection disabled (it rendered the scene, and every CSM cascade, twice more once any transparent material existed). SMAA search preset follows the level (LOW/MEDIUM/HIGH/ULTRA).
- **CSM:** cascades ≥ `CSM_THROTTLE_FROM` (2) re-render every 2nd frame, staggered (a skipped cascade keeps its map AND shadow matrix; +4 % box margin; a camera jump > 8 m re-renders all). `setNearCasters(lighting, renderer, camera, root, dMin, dMax)` (lighting.ts) renders a subtree (the player car) only into the cascades whose view-depth range (+ CSM fade band) overlaps [dMin, dMax]; it toggles `root.visible` per cascade inside `renderer.shadowMap.render` (three tests layers against the VIEW camera in the shadow pass, so layers cannot do this).
- **Low preset paths:** terrain `TERRAIN_LITE` define (one planar tap per layer: no hex tiling, no triplanar side planes, no far detail), arrays at 512² and anisotropy 1; roads `RD_LITE` (one tap per map); terrain/road texture anisotropy low 1 / medium 4 / high+ max (`anisotropyFor`). Switched by `setQuality` (defines → recompile).
- **Software WebGL** (`isSoftwareRenderer`: SwiftShader/llvmpipe): default level low when nothing is stored, and the final pixel ratio is capped at `SOFTWARE_GL_PIXEL_RATIO` 0.5 (`QualityControllerOptions.maxPixelRatio`); `?swcap=0` lifts the cap.
- **Boot:** programs are compiled against the composer's HalfFloat target (compiling for the canvas built a second, sRGB-output copy of every program), the vehicle bodies are built and pre-compiled while the terrain generates, the terrain texture arrays are packed in that window too, and there is one first frame (no separate warm-up render). Main no longer re-hashes the transferred terrain (the physics worker's hash comparison stays).
- **Profiling:** `?perf=1` (or the ` key) → `src/app/perf.ts` (`FrameProfiler` sections, `PassCounter` draws/triangles per composer pass and per cascade) + the lazily loaded overlay `src/ui/perfOverlay.ts`; `?perf=gpu` also times each pass with a readPixels sync; `window.__crumple.perf` exposes the same data plus the loading-stage marks. `tools/perf-probe.mjs` drives it headlessly.

## patchMaterial — FROZEN (P3)

`patchMaterial(material, {csm?, flexbody?, damage?}) → {color, depth, distance}`; assign `mesh.material`, `mesh.customDepthMaterial`, `mesh.customDistanceMaterial`. **Order (`PATCH_ORDER`): CSM first, then flexbody, then damage.** CSM: `csm.setupMaterial(color)` runs first because it overwrites `onBeforeCompile`; patchMaterial captures that hook and composes `prior hook → features in order`; CSM never touches depth/distance. Flexbody (P4 `ShaderPatch`) applies to color AND depth (RGBADepthPacking) AND distance, so shadows deform with the body. Damage (P4) applies to color after flexbody. `customProgramCacheKey` = prior key + feature keys in order; patching the same material twice throws. Every shadow-receiving lit material (terrain, roads, vehicles, props) must be patched with `csm`.

### BindingSet v2 — pending FREEZE (end of P4)
`bindPanels(compiled, def, geoms) → BindingSet{vehicle, nodeCount, rigHash, panels: BindingPanel[], stats}` (A2, pure, deterministic). Per panel, per vertex, **K = `FLEX_TRIADS` = 3 blended triads**: `triad` Uint16 K×(iR, iX, iY) object-local, `coef` Float32 K×(a, b, c, d0), **`weight` Float32 K (Σ = 1, descending)**, `frameNormal` K×xyz (rest normal in each triad's rest GS frame), `frameTangent` K×xyz | null (handedness = `restTangent.w`); plus `restPosition`, `restNormal`, `restTangent|null`, `uv`, `index`, `damageWeight`, `nodes`, `bindNodes`, rest bounds, resolved `detach.attachBeams` / `glass.beams` (object-local beam indices), `lights`, `castShadow`. `stats` adds `poolTriads`, `meanTriads`.
- **WHY v2 (P4 polish):** with one triad per vertex, neighbouring vertices that picked different triads extrapolate differently under a non-affine crush, so heavy crush tore the skin into jagged shards with holes. A continuous K-blend keeps neighbours together (regression test: synthetic crumple field, neighbour displacement jumps ~0.55× single-triad).
- **Triad pool + selection:** per panel, every triple among each bind node's `FLEX_POOL_STEPS[0]` (8) nearest bind nodes, deduplicated, R = the corner nearest 90°, static acceptance as before (angle ∈ [25°, 155°], edges ∈ [0.04, 1.6] m, ratio ≤ 6); reference point g = centroid, size ρ, conditioning κ = 1 + 0.5(1 − sin θ_R). Per vertex the K + 1 accepted triads (|c| ≤ 0.3 m, |a|, |b| ≤ 3) with the lowest μ = κ(|P − g| + 0.5ρ) (exact grid ring search); weights w_k ∝ 1/μ_k − 1/μ_K (inverse distance minus the first rejected candidate's: a triad's weight reaches 0 exactly where it swaps out, so the surface is continuous), normalized; fewer candidates → plain 1/μ, unused slots repeat triad 0 at w = 0. Repair = rebuild the pool with 16 nodes, then every triple (capped at a 32-node neighbourhood above 120 k triples), else `BindError` (never outside the bind set). Seams: bit-equal rest positions (quantum 1e-5 m) share identical triads, coefficients and weights.
- **Reconstruction (shader == `evalFlexVertex` CPU mirror), per triad:** `e1 = X−R, e2 = Y−R, cr = e1×e2, m = max(|e1||e2|, 1e-4)`, `n = cr / max(|cr|, FLEX_SIN_FLOOR·m)` (unit while sin θ ≥ 0.15; shrinks as the triad collapses → the c offset folds flat instead of flipping), `o = a·e1 + b·e2 + c·n`; **graceful clamp** `lim = 1.5·d0 + 0.1 m`: `|o| > lim → o·lim/|o|` (length-limited, continuous; non-finite → 0), never snapped to R; quality `q = (1 − smoothstep(1.15·d0 + 0.02, lim, |o|))·smoothstep(0.075, 0.3, sin θ)` (0 when clamped), `W_k = w_k·max(q, 1e-3)`. **Blend:** `P̄ = ΣW P_k/ΣW`; consensus `C_k = W_k/(1 + |P_k − P̄|²/0.05²)`; `P = ΣC P_k/ΣC`; frames `N_k = F_k·fn_k` (GS frame), `N̄ = normalize(ΣC N_k)`, `A_k = C_k(0.05 + smoothstep(−0.2, 0.8, N_k·N̄))`, `N = normalize(ΣA N_k)`, `T = GS(ΣA T_k against N)`. Rest and rigid motion are exact (all P_k / N_k agree). Constants and the full spec: `types.ts` "FLEXBODY RECONSTRUCTION v2".
- **Crumple folds (GPU-only cosmetic):** the vertex stage adds `FLEX_CRUMPLE_AMP (0.04 m)·strain·damageWeight·flexCrumple(rest)` along N in color, depth and distance (shadows fold too); `flexCrumple` (`FLEX_CRUMPLE_GLSL`, rest space: accordion ridges across z + isotropic buckles) is also added to the damage bump height so the folds shade. Zero for a pristine body, so CPU/GPU parity holds wherever strain is 0.
- **Settle calibration (flexskin, not part of the binding):** the visual bind pose is the SETTLED pose. Light sub-rigs sag at rest in the sim (sedan `hood_2C` −5.8 cm: no support rest under it; trunk lid ~7 cm), which showed as dents with the engine poking through on an undamaged car. Within 6 s of each spawn/repair, once upright, still and unbroken, the per-node deviation from the rigid rest pose (frame-node basis) is averaged over 0.4 s and from then on subtracted (rotated by the frame basis, faded in, gated by uprightness so a car on its roof is not double-bent). Body nodes only (tyre squash stays real).
- **Node texture** (one per vehicle, A2): RGBA32F, width 64, Nearest, height 2·rows (rows = ⌈nodeCount/64⌉), texel of node i = (i & 63, i >> 6 [+ rows for block B]), `texelFetch` only. Block A = skin-space xyz (world − anchor, anchor = frame-origin node) + w = flags (`NODE_TEX_FLAG_BROKEN` 1 = a beam at this node is broken, `NODE_TEX_FLAG_DETACHED` 2); block B = (strain, scuff, glass crack, 0). Written every frame from `SimClient.interpolate` (A block by the skin, B block by damage), one upload per frame.
- **Shader patch** (`flexbody`, key **`flex2`**, color + depth + distance via `patchMaterial`, order CSM → flexbody → damage): attributes `flexTriad{0,1,2}` vec4 (iR, iX, iY, w), `flexCoef{0,1,2}` vec4 (a, b, c, d0), `flexFrame{0,1,2}` vec4 (fn.xyz, ft.x), `flexFrameT` vec4 (ft0.yz, ft1.yz, color only), `flexFrameU` vec4 (ft2.yz, damageWeight, 0) — active slots color 11 + position/uv/tangent = 14, depth 11 (≤ 16); `flexEvaluate()` runs first in `main()`; uniforms `uFlexNodes`, `uFlexRows`; color target exports `vFlexRest` (rest position) and `vFlexDamage` (block B blended over all 3 triads' nodes, w_k × barycentric, × damageWeight; w = Σ w_k·[triad has a broken node], continuous) under `#define FLEXBODY`. Texel fetches per vertex: 9 (block A) + 9 (block B). Per-panel bounding spheres are recomputed from the panel's nodes every frame (+ 1.5·max d0 + 0.1 + crumple amplitude).
- **Wheels** are not panels: rigid frame from hubs + rim phase, tyre radial squash interpolated between tyre-ring rays (never per-node triads: a 12-ray ring would facet), as a `flexbody`-slot patch with key `wheel1` so shadows deform too.

### Damage data flow (main-side; one additive protocol section)
- **Broken state:** new always-present snapshot section, a **broken-beam bitset** (bit g = global snapshot beam g broken), authoritative for node BROKEN flags, panel detach and glass broken fractions. WHY a section rather than events alone: the beamBreak ring holds 256 per snapshot (a big crash or glass shatter can overflow it), and P7 replay seeks restore states for which no events exist. Cost ⌈beamCapacity/32⌉ words (16 KB at default capacity), packed from `active` while writing the snapshot.
- **Repair epoch** per object (`OBJ_REPAIR_EPOCH`, the former reserved word 6): +1 per `reset`; a change clears all damage visuals (in-flight pre-repair snapshots cannot re-damage the body).
- **beamBreak events** → immediate FX + early detach/shatter check (bitset confirms). **impact** → scuff deposit (falloff over 0.35 m, full at 300 N·s) and glass crack/shatter by impulse. **skid** away from tyre nodes → light scrape scuff.
- **Plastic strain: derived on main, no protocol change.** Per snapshot: `e_b = |L/L0 − 1|` for every intact body beam (L0 = `CompiledRig.beamRestLen`), node strain = max over incident beams, min over the last 3 snapshots (drops elastic transients < ~25 ms), ratcheted through a 1 % deadzone to full at 8 % (`DAMAGE_DEFAULTS`). WHY: yield in this sim is a lasting rest-length change, so it shows directly as current-vs-original length; ~2 k beams × 120 Hz is < 0.1 ms on main vs a per-beam f32 section.

### Static colliders

### P4 crash amendments (A5; harness `src/sim/vehicle/crash.ts`, report via `crash.test.ts`)
- **Beam kernel plasticity** (`src/sim/beams.ts`): `PLASTIC_RATCHET` 0.02 → 0.1 (force overshoots `deform` in proportion to the crush rate: rate-dependent resistance and tearing), `PLASTIC_WEAKEN` 0.985 → 1 (weakening increased spring-back), **compression lockup** `PLASTIC_COMPRESS_FLOOR` 0.3 (plastic shortening stops at 0.3·L0; a beam at the floor never breaks in compression), **reverse-yield hysteresis** `PLASTIC_REVERSE_FACTOR` 2 (a plastically shortened beam yields in tension only at 2× `deform`, a stretched one in compression likewise; with symmetric yield the energy stored around a crushed zone pulled the folded rails straight again: 50 km/h peak 96 cm → final 37 cm).
- **Vehicle MINIMASS by group** (`builder.ts`): `vehicleOmegaDtLimit(group)`: tread 0.49 (P2), **crash shell group `SHELL_GROUP` = 'body' 0.495** (`SHELL_OMEGA_DT_LIMIT`, under the 0.5 hard limit), everything else 0.35; validation judges each node against its group limit. Why: crash response is stiffness-limited (elastic travel before yield = spring-back). Contact adds ≤ sqrt(0.2) in quadrature (≤ 0.68 per node).
- **Collider kernel details** (`colliders.ts`, within the frozen law): the inside-solid face skip applies only when that face is deeper than min(0.1 m, half the solid's extent along it) (a REBOUNDING node in a legit contact also has v·n > 0 at its nearest face); the penalty spring uses min(depth, 0.12 m). Cylinder radial skip → push out of the opposite side.

### Sim (U1) — node-vs-node, sleep, water, props
- **Phase order (amends canonical rule 3/5):** per AWAKE object ascending: vehicle pre-step → hydros → beams; then (every `rebuild` ticks) broadphase + sleep/wake; then the node-vs-node pass over the cached pair list (canonical order); then per awake object ascending: water → ground → colliders → integrate. Splitting the loop is bit-identical for objects with no object/water contact (per-node accumulation order beams → ground → colliders is unchanged); the determinism test stays green and a new one covers props + contact.
- **Broadphase:** rebuild every 8 ticks (16 while every awake object is slower than 2 m/s). Object AABBs of awake objects fattened by `max node speed · rebuild·dt + 2·max objRadius`; sleeping objects use their transformed proxy box. Overlapping object pairs (lower id first) → spatial hash of the overlapping nodes (cell = 2 × max objRadius of the pair) → candidate node pairs with distance < r_a + r_b + margin, SORTED (lower objectId node first, then node index a, then b); capacity 32768 pairs per rebuild, overflow drops the tail (deterministic) and is counted. Same-object pairs are never generated.
- **Contact law (sphere–sphere, `RigNodeDef.objRadius`, flag `objContact`):** depth = r_a + r_b − |d|; m_r = m_a m_b/(m_a + m_b) (pinned node: m_r = m_free); k = min(`OBJ_KC_MAX` 1e6, 0.2·m_r/dt²); c = 2·0.65·sqrt(k·m_r); Fn = max(0, k·depth − c·v_rel·n); friction implicit backward-Euler on the relative tangential velocity, F_req = −m_r·v_t/dt clamped to μ·Fn, μ = sqrt(μ_a·μ_b) (node friction); equal and opposite. Only + − × ÷ sqrt, zero allocation. Events: impact for BOTH objects (lower id first) when m_r·approach speed ≥ 2 N·s (`materialId` = the other object's contact material: PropDef.material, vehicles metal; normal into the receiving object); skid (scrape) with the ground thresholds and the shared per-node cooldown.
- **CompiledRig additions (U1, `compileRig`):** `nodeObjRadius: Float64Array` (default 0.6 × median incident beam rest length, clamped [0.04, 0.35]; prop nodes ≥ `PROP_MIN_OBJ_RADIUS`), flag `RIG_NODE_FLAG_OBJ_CONTACT` (1<<3, = sim `NODE_FLAG_OBJ_CONTACT`); `SimState.objRadius` (f64). Collision-only nodes = `collidable: false, objContact: true` (mid-panel nodes against interlock; the sedan gets them only if playtests show interlock).
- **Sleep:** `PropSleepParams` (default linearSpeed 0.05 m/s, holdS 0.75 s, startAsleep true): checked at rebuilds; asleep = skipped by every pass, velocities 0, `OBJECT_FLAG_SLEEPING`. Wake = an awake object's fattened AABB overlaps the sleeping box (propagates once through touching sleeping boxes: a stack wakes together), `resetProps`/`spawnProps{asleep:false}`. Vehicles never sleep.
- **Water (`WATER_PHYSICS`, `src/world/types.ts`):** per awake collidable node in a body's rect with y − 0.15 < level: f = clamp((level − y + 0.15)/0.3, 0, 1), V = m/ρ_obj (PropDef.density, vehicles 900), buoyancy ρ_w·g·V·f up, drag −f·(0.8·m·v + 0.5·ρ_w·1.0·(V/0.3)·|v|·v), drag impulse capped at m·|v| per tick.
- **Props:** `PropDef{key, name, rig (base on y = 0, front −Z), surface, material, density, stackHeight, proxy, sleep, anchor, frame}` with `PROP_RIG_BUDGET` per key and the node-id prefixes in `src/sim/props/types.ts` (U2 binds by them). Catalog keys: cone, barrel (200 L), tire, boxCardboard, boxWood, signPost, lightPole, concreteBlock. **Breakable sign post / light pole = PINNED anchor nodes** (`mass ≤ 0`) tied to the base by anchor beams with `anchor.breakF` (signPost ≈ 15 kN, lightPole ≈ 40 kN; a 50 km/h sedan snaps both); `ColliderDef.breakable` stays RESERVED and unused. Concrete block 1000 kg, near-rigid beams. `resolvePropInstances` (pure, both sides) expands rows × stacks, resolves y, builds the yaw quat from `facing` with sqrt only, validates (unknown key, stack on non-stackable, > 256 instances, overlapping proxies) and copies `surface`/`material` into each `PropInstance`.
- **P4 follow-up:** sedan `hood_2C` and trunk-lid support rests (compression-only `support` beams from the hood/lid centre rows to the bay/rear structure, elastic, snap at 15 kN like the P4 hood rests) so the settled body does not sag: static sag ≤ 1 cm (hood_2C) / ≤ 1.5 cm (trunk lid centre) after 2 s; handling + crash harnesses stay green. The render-side settle calibration stays as a safety net.

Brute force ≤ 2048 tests per object pair, else a spatial hash (adaptive table ≤ 4096). ### FX event → effect (U3)
Classification: an event is a TYRE contact when its position is within tyre radius + `FX_TYRE_CLASSIFY_MARGIN` of a registered vehicle's hub midpoint; otherwise the mover is the object's surface (vehicles metal, props `PropInstance.surface`). Hard ground = asphalt, concrete, rock, metal; soft = grass, dirt, gravel; object materials 7–10 behave per their surface.

| source | condition | effect |
|---|---|---|
| wheel telemetry (per frame, registered vehicles) | hard ground, slip ≥ 3 m/s | tyre SMOKE (rate ∝ (slip − 3)·load, white-grey, lingers, drifts with slow-mo-scaled time) |
| wheel telemetry | hard ground, slip ≥ 2 m/s, load ≥ 800 N | SKIDMARK ribbon (dark rubber, width = tyre width, opacity ∝ slip·load) |
| wheel telemetry | soft ground, slip ≥ 1 m/s | RUT mark (darker, wider, material-tinted) + DIRT/GRAVEL/GRASS spray (clods + dust, material colour) |
| wheel telemetry | dirt/gravel, ground speed ≥ 6 m/s | rooster-tail DUST (behind the wheel, ∝ speed) |
| skid event, non-tyre, metal/concrete mover | hard ground, slip ≥ 2 m/s, load ≥ 100 N | SPARK stream + light scrape mark (pale grey) |
| skid event, non-tyre, other movers | any | DUST puff (soft) / CHIPS of the mover's surface (hard), no sparks |
| impact event, metal/concrete mover | hard ground or metal/concrete object material, impulse ≥ 6 N·s | SPARK burst (count ∝ impulse) + small dust puff |
| impact event | soft ground, impulse ≥ 10 N·s | DIRT clod puff |
| impact event, plastic/cardboard/wood/rubber mover or object material | impulse ≥ 6 N·s | CHIPS of that surface (plastic shards / cardboard flakes / wood splinters), no sparks |
| beamBreak event | vehicle | DEBRIS chunks (paint-coloured + black plastic) + a few sparks if metal |
| beamBreak event | prop | DEBRIS of the prop surface (splinters, flakes, concrete chunks, cone shards) |
| nodes vs water (main-derived) | node crosses level downward ≥ 1.5 m/s | SPLASH (crown + droplets, ∝ Σ m·v per object per frame) |
| nodes vs water | horizontal speed in water ≥ 2 m/s | WAKE spray (continuous, ∝ speed) |
Glass shatter/cracks stay in the vehicle's own `shatter.ts` (U6 dir); FX never handles `DamageFx`.

### Decisions
- **Scheduling is worker-internal (no promote/demote/spawn commands).** Main sends one `setTraffic` (variants as plain VehicleDefs + seed + density + focus objectId) and optional `setTrafficDensity`; the worker owns the route network, the driver model, the awake ⇄ ghost scheduler, the respawns and the awake objects (`objectId = TRAFFIC_ID_BASE 100 + agent`). Why: every decision depends on sim state (player pose, contacts, damage); on main it would depend on frame timing and each decision would have to be shipped back and logged. In the worker it is a pure function of (seed, command log): the determinism hash and the P7 replay cover traffic for free. The P1-reserved `setBubble` is SUPERSEDED (the bubble follows `focusObjectId`; still `unimplemented`).
- **Determinism rules for T1:** the driver model and scheduler run every `TRAFFIC_AI_TICKS` = 20 ticks (100 Hz) at the START of a tick, before phase 1; agents in index order; only `+ − × ÷ sqrt` (pure pursuit needs no trig: κ = 2·y/L², wheel angle by the rational atan `x/(1 + 0.28x²)` for |x| ≤ 1); rng = `core/rng` seeded from `setTraffic.seed` only; spawns/despawns of awake cars at that tick boundary; P7 keyframes must include the traffic state (agents, rng). The governor's input (`workerLoad`, wall-clock) never reaches the sim: main answers it with `setTrafficDensity`, a logged command.
- **Ghost ⇄ soft-body hand-over (no pop):** at `setTraffic` the worker settles each variant 1.5 s on a private plane and re-aligns it to the rest frame: the SETTLED TEMPLATE (`TrafficReadyMsg.variants[i].settled`, rig-local). Ghost pose = `routePose(path, s)` (vehicle-frame placement, rig ground plane on the lane surface); promotion spawns exactly `pose · template` with the rigid velocity `speed·forward` and pre-spun wheels; main bakes the ghost instance meshes from the same template (flexbody binding evaluated at those nodes). Render swaps instance → soft body when `nodesReady` (object in both interpolation snapshots), so neither side jumps. Demotion projects the car onto its path (≤ 0.5 m / 5° snap, else the car is off-route: recycled instead); the record carries `TRAFFIC_FLAG_TELEPORTED` whenever a pose jumps.
- **Bubble:** promote at ≤ 110 m, demote at ≥ 160 m from the focus frame origin (`TRAFFIC_BUBBLE_DEFAULTS`). Promotion candidates by distance ascending (tie: agent index). No free slot: swap out the farthest UNDAMAGED awake car that is ≥ 20 m farther than the candidate; else the candidate stays a ghost, and a ghost that cannot be promoted is recycled before it gets within `TRAFFIC_CONTACT_M` 45 m (ghosts never touch anything).
- **Recovery:** an awake agent is WRECKED (hazards on, throttle 0) when telemetry damage > `TRAFFIC_WRECK_DAMAGE` 0.15, frame up·Y < 0.5, it has been > 6 m off its path for 3 s, or STUCK (< 0.5 m/s for 8 s with nothing ahead and no yield). Wrecked/stuck cars are despawned and respawned only OUT OF SIGHT: ≥ 120 m from the focus, or > 40 m and > 100° off the focus heading. Respawn points: ≥ `TRAFFIC_SPAWN_MIN_M` 250 m from the focus, never in its forward ±70° cone closer than `TRAFFIC_SPAWN_CONE_M` 600 m, ≥ 30 m from any agent on the same path. A dead-end U-turn the awake car fails is the stuck rule's job.
- **Drivetrain for 4WD:** not supported. `DrivetrainDef` has one diff across all driven wheels; a 4-wheel `locked`/`limited` diff forces equal front/rear ω and scrubs in every bend (no centre diff / transfer case). The pickup is RWD with a limited-slip diff. A real 4WD (centre diff) is a P9 candidate.
- **Box truck budget: no exception.** 6 wheels × 10 rays (front singles, rear duals: 4 × 223 + 2 × 223 ≈ 1340 wheel beams) + body ≤ 2160 fits the 3500 player budget; heavy nodes allow stiff beams under the ω·dt rule, so the body needs no more. If the duals do not fit with a body that meets the crash/tip targets, F3 falls back to 4 wide singles, never above 3500. A heavier focus rig reduces awake traffic instead (the pool rule below).
- **No shared fleet generator.** Each fleet def is its own generator module (copy and adapt `defs/sedan.ts`; never import from or edit it). Tyre tunings live in each def file (`wheelrig.ts` `WHEEL_TUNING_205_55R16` stays the sedan's). A shared lattice kit is a P9 clean-up candidate.

### RouteNetwork (T1, `src/world/routes.ts`; types in `src/world/types.ts`)
`buildRouteNetwork(layout, terrain) → RouteNetwork{paths, junctions, laneCount, laneLength, hash}`, `routePose(path, s, out)`, pure, generator numerics. Right-hand traffic; lane k of direction dir at road-frame offset `dir·(k + 0.5)·width/(2·lanes)`. Routed kinds `TRAFFIC_ROAD_KINDS` = highway, country, mountain, street (dirt trail and arena runway: none). `RoutePath` = a LANE (one direction-lane between junction boxes, cut `JUNCTION_BOX_M` 12 m from each junction centre) or a CONNECTOR across a junction box (Hermite curve lane end → lane start: straight, left, right; a U-turn at dead ends), each with its own station polyline (`ROUTE_STATION_STRIDE` 8 = x, y, z, tx, ty, tz, bank, curvature every 2 m, offset and bank applied), `next/prev`, `speedLimit`, `yield`, `conflicts`, `left/right` neighbour lanes. **Speed limits** (`ROUTE_SPEED_LIMITS`): highway 110, country 80, mountain 60, street 50 km/h; turn connectors ≤ 40, U-turns ≤ 15. **Junction rules:** through road = the highest-priority routed road; through connectors never yield except left turns (yield to the opposing straight); every branch connector yields to the through connectors it conflicts with (paths within 2.5 m, or merging into one lane).

### Driver model (T1, worker)
- **Longitudinal = IDM** per agent: `a = a_max·[1 − (v/v₀)⁴ − (s*/gap)²]`, `s* = s₀ + v·T + v·Δv/(2·sqrt(a_max·b))`, a_max 1.6 m/s², b 2.8 m/s² (hard limit 7), T 1.4 s, s₀ 2.5 m; per-agent "temperament" (seeded) scales v₀ 0.92–1.06 and T 1.2–1.7. v₀ = min(speedLimit·temperament, curve speed `sqrt(2.6 m/s² / |κ|)` over the lookahead with braking distance `sqrt(v_c² + 2·b·d)`). The leader is the nearest agent (ghost or awake) or the FOCUS (player) whose footprint lies within the lane corridor (± lane width/2 + 0.3 m) along the path ahead (next paths followed by the agent's planned route); the player also counts when stopped across the lane in a junction. **Junction yield:** a yielding connector is entered only if no conflicting agent will be inside the junction box within 4 s (or is in it); after 6 s waiting it goes when the box is physically clear (deadlock breaker).
- **Lateral = pure pursuit** on the path polyline: lookahead `L = clamp(0.9·v + 4, 6, 28)` m, κ = 2·y_local/L², wheel angle `δ = atanR(κ·wheelbase)` (rational), steer = δ/δ_max clamped to ±1, slew ≤ 2.5/s. Awake cars turn (IDM a, δ) into ActionState: throttle/brake by a speed PI on v_cmd = v + a·0.5 s, auto box in Drive, handbrake only when parked.
- **Route choice** at each lane end: a seeded weighted pick among `next` (straight 0.6, right 0.25, left 0.15, renormalized over what exists); U-turn only at dead ends. Lane changes (highway only): to the right lane when free (keep right), to the left to overtake a leader slower than 0.8·v₀, gap ≥ 2 s both ways, 3 s manoeuvre with indicators.
- **Ghosts** integrate `s += v·dt`, `v += a·dt` with the same IDM and leaders (awake cars and the player included), pose by `routePose`; zero soft-body cost.

Measured: sag 5.0 cm, 0–100 6.8 s, 100–0 35.8 m, R40 0.98 g, 50 km/h crush 55 cm (peak 110) / intrusion 2 cm; accelerates at 200 km/h but a 10 s WOT run from 195 ends at ≈ 179 km/h (10-ray tyre rolling loss; irrelevant at the 117 km/h traffic ceiling).
- **Settled template** (`traffic/templates.ts`): 1.5 s on a private asphalt plane, neutral, brakes on; re-aligned so the frame basis and the frame origin's x/z equal the rest frame, the settle HEIGHT kept, so the rig ground plane y = 0 is the road (tread nodes sit ≈ 3.5 cm into the soft contact layer, as on the road). Awake record pose = `Q = R_now·R_restᵀ` (R = [right, up, forward] from the frame nodes), `pos = origin_now − Q·origin_template`; a promoted car measures exactly its ghost pose (1 cm / 0.000° after one tick, `driver.test.ts`).
- **Route network:** junction boxes are 12 m, longer where a road meets another at a shallow angle (its lane ends clear the other carriageway + shoulder by 3 m: `(W/2 + shoulder + 3)/sin θ`, ≤ 30 m); dead-end lanes stop 14 m before the road end and the U-turn is a loop of radius max(width/2 + shoulder, 6 m) beyond it; connector ends copy the lane tangents (heading continuity). Right of way as a priority: through straight/right 3 > through left 2 > branch straight/right 1 > branch left / U-turn 0; a yielding connector waits only for conflicting connectors of higher priority (equal: the higher path index yields). Crumple Valley: 122 paths (44 lanes, 24 km), hash `0xcc2b064f`.
- **Driver additions:** desired speed = min(limit·temperament, a per-path backward curve envelope `sqrt(v_c² + 2·b·Δs)`, the next plan paths' limits braked back) — O(plan) per tick, the whole plan rather than a fixed lookahead. Lateral: pure pursuit from the rear axle + an understeer feed-forward `K_us·v²·κ` (K_us 0.0055 rad per m/s²; pure pursuit alone ran 2 m wide at 110 km/h) + a slow cross-track integral; highway lateral error ≤ 0.11 m at 31 m/s. Throttle capped at walking pace / large steer (TC cannot cut below 2.5 × idle; flooring it in a tight junction turn spun the rears). Obstacles = props more than 0.5 m from where traffic first saw them (refreshed at 25 Hz), ignored once under the bumper. `TrafficAgent.hold` / `TrafficSim.placeAgent` are tool/test hooks (a held car is exempt from the stuck rule).
- **Budget (measured, `traffic/budget.test.ts`; this shared box ran at load 8–15 on 4 cores, where the player sedan alone measured ≈ 300 ms/sim-s against U1's quiet 200):** one awake traffic sedan adds ≈ 150–290 ms/sim-s there, i.e. ≈ 100–190 scaled to the quiet box (its beams are 72 % of the sedan's; target 120); 28 ghosts + route network + scheduler ≈ 0.13 ms per AI tick = 13–22 ms/sim-s loaded (target 5). Both need a re-measure on a quiet box before the governor thresholds are tuned.

## P7 contracts — replay + cameras

Contract files (change only via this doc): `src/protocol/replay.ts` (new: `ReplayFile`), `src/protocol/messages.ts` (additions below), `src/app/replay/types.ts` (new: the R2-facing `ReplayController` API, buffer presets, markers, targets, `window.__crumple.replay`), `src/render/fx/types.ts` (three additive replay hooks). Full rules live in those files' doc comments; this section is the summary + the decisions.

### Decisions
- **Two mechanisms.** (1) The LIVE REPLAY BUFFER (scrub, slow-mo, reverse, free cam) records on MAIN what the renderer consumed; playback presents recorded frames through `SimClient`, so every consumer renders replay frames through its normal path. (2) The REPLAY FILE is the worker's deterministic command + input log since `init`; re-simulating it reproduces the run's state hash (P8 ghosts, export). This supersedes PLAN's "input log plus keyframes every ~2 s; scrubbing re-simulates": re-simulating 2 s of a crash at 2 kHz (≈ 0.5–1.5 s CPU with props and traffic) per scrub step cannot scrub interactively, and a full sim-state keyframe (engine + traffic + contacts + runtimes) is a large serialization surface for no visual gain.
- **Recording lives on main.** Main already receives every snapshot and is where playback must end up (the renderer); a worker recorder would compete with the physics budget (the tightest budget in the game, CONTRACTS "Awake budget") and would have to ship frames back on every seek. Main-side cost is a quantize pass over awake objects per recorded frame (measured below) at 60 Hz, inside the frame budget.
- **What a recorded frame holds** (everything the renderer reads from a snapshot): header (tick, simTime, timescale), per object (ascending id) id / flags / node + beam counts / repair epoch, node positions quantized to 16 bit per axis in the object's per-frame bbox (f32 min + scale), telemetry (vehicles: 32 f32, raw), broken-beam bits (objects with any broken beam), the traffic records (raw 64 B), the impact / beamBreak / skid rings (raw, aggregated over decimated snapshots; traffic TELEPORTED flags OR-ed in). Not recorded: the debug strain section (the beam view shows unstrained beams in replay), worker load. Sleeping objects whose state is unchanged since the previous recorded frame are stored by reference; every `keyframeEvery`-th frame stores everything (eviction drops whole keyframe groups, so references never dangle).
- **Pause, not rewind.** `replayPause` freezes the worker (state untouched); exit resumes the same deterministic run. Main sends no commands while replaying.
- **Seek + FX + damage.** A settled seek bumps a seek generation that SimClient adds to every presented repair epoch (and keeps on the live view after exit), so all damage visuals (vehicle, traffic pool) reset and re-derive from the frame: broken bits → detach / shatter, geometry → crumple shading (`damage.ts`: after an epoch change the first strain measurement seeds the persistence filter, so a paused frame shows its crush at once; live behaviour unchanged since a repair snapshot is at rest). FX: `clearTransient` + `reseed(hash(start frame))` + re-run of the emitters over the recorded frames of the last `REPLAY_FX_PRIME_S` (events routed exactly as live), so particles and debris at the target are deterministic. Skidmarks are not re-laid (`setSkidmarksFrozen` while replaying): the live marks already cover the buffer and the shader hides marks born after the presented time. Impact scuffs are re-fed from the prime window only (older scuffs reappear only as their frames are played).

### P7 Replay — R1 as built (additive; supersedes the bullets above where they differ)
- **Worker** (`src/sim/worker.ts`, `src/sim/replay/{log,hash,resim}.ts`): `ReplayLog` logs every `REPLAYABLE_COMMANDS` message at `engine.tick` BEFORE applying it (rejected ones too) and, per `input`, the actions whose clamped value changed (chunked SoA typed arrays, 16 K entries per chunk, cap `REPLAY_INPUT_LOG_MAX`). `init` restarts the log; `groundHeightfield` records the layout ref (id, version, the worker's terrain hash). `replayPause` sets `WorkerHost.paused` (wakes re-base the clock and take no steps; dirty snapshots are still sent) and answers `replayPaused` with `hashSimState`; `stateHashRequest` / `replayFileRequest` answer as contracted (input arrays transferred). `hashSimState` = FNV-1a over tick, object table + actions, every used node's pos + vel (f64 bits), every used beam's restLen / k / active, live traffic agents (path, s, v, awake, look). `resimulate(file, {terrainDeps?, toTick?})` replays a file on a fresh host (inputs re-applied through `input` so the re-run logs the same file). Tests (`src/sim/replay/replay.test.ts`): a 4 s sedan run on a plane with a collider wall, props, irregular wakes (8–40 steps), late buffer returns (pool misses), a timescale change, a pause + hash request, recover / setAssists / resetProps / reset and a rejected input re-simulates to the identical hash (and re-exports the same log); the same on Crumple Valley with the layout props and 12 traffic agents (promotions); a perturbed input diverges.
- **Recorder** (`src/app/replay/buffer.ts` `ReplayBuffer`, pure): frame record layout in its header comment (16-word header incl. the event offset, 8-word object table, data blocks, events + traffic in protocol word layout). Node quantization: f32 min + f32 scale per axis per object per frame, u16 q = ⌊(x − min)·(1/scale) + 0.5⌋ against the STORED f32 values (decode error ≤ scale/2: 0.04 mm on a 5 m car), non-finite → q 0. Telemetry stored only for ids below `PROP_LAYOUT_ID_BASE` with a non-zero slot; broken bits only for objects with ≥ 1 broken beam, read word-level through the additive `SnapshotReader.readObjectBrokenBits(i, out)` (object-local packed bits + popcount). REPEAT = asleep now and in the previous recorded frame, same epoch + node count, data frame ≥ the group's keyframe. Recording is driven by `SimClient.setSnapshotSink` (every live snapshot; `record()` decimates at `⌊2000 / recordHz⌋` ticks; `recordNow()` on entry so the buffer ends exactly at the live view). Events are staged across decimated snapshots (caps 4× the protocol rings, overflow counted in `stagedDropped`).
- **Recorded rate = what main receives.** Main gets about one snapshot per rendered frame when a frame is longer than the 8 ms snapshot interval (the 3-buffer pool), so the buffer holds `min(recordHz, fps)` frames per second (60 Hz at 60 fps; ≈ 1–2 Hz under SwiftShader, which is why the e2e drives with the render loop held). Acceptable: slow-mo interpolates linearly between frames.
- **Markers:** impacts are classified tyre / body when STAGED, against the snapshot that carried them, with a SWEPT test (within tyre radius + 0.15 m of the segment from each hub midpoint back along the COM velocity over the time since the previous snapshot + 10 ms: at 100 km/h a skipped snapshot puts the contact metres behind the carrying snapshot's hubs). `ReplayDeps.wheelsOf` (main: the player's `CompiledWheel` hubs) — traffic without hubs counts every impact. Severity / merge as contracted.
- **Playback** (`src/app/replay/index.ts`): decode into a 3-slot cache of snapshot buffers (recorded capacities, debugStrains off: the beam view shows unstrained beams in replay) keyed by (sequence, seek generation); `presentAt(t)` presents (frame before, first frame ≥ t); forward play captures the event rings of every frame passed (`decodeEvents`, header + events only); reverse play bumps the generation EVERY frame (damage re-derives from each frame: no ratchet backwards) and delivers no events; reaching an end, pausing after reverse or playing forward after an unsettled seek runs a settle. `step(+n)` from a consistent state plays the frames (events, FX continue), `step(−n)` is a settled seek. Quality changes while replaying apply on exit (a new preset drops the buffer).
- **SimClient seam** (`src/app/simClient.ts`, R1-internal): `setSnapshotSink`, `beginReplay` (live prev/cur parked, live snapshots arriving meanwhile parked: newest kept, older returned), `presentReplay(prev, cur, time, events)`, `pushReplayEvents`, `discardEvents`, `endReplay(epochOffset)` (live repair epochs + offset from then on), `pauseSim`, `stateHash`, `requestReplayFile`, `objectNode(id, local, time, out)`, `objectBounds(id, out)`, `replayActive`, `liveReader`. `renderTime()` answers the playhead while replaying.
- **Settle (main, `ReplayVisualHooks`; superseded for the player / props by the checkpoints below):** present the OLDEST held frame → `primeBegin(seed)` (interpolate, update the vehicle visuals + traffic once: the new generation resets every damage visual; drop queued events; `fx.clearTransient()`, `fx.reseed(seed)`, seed = hash of the FX-window start frame's sequence) → for every held frame up to the target that lies in the FX window (`REPLAY_FX_PRIME_S` = 6 s) or carries `FRAME_BODY_HIT` (header word 13: a non-tyre impact ≥ 3 N·s on a vehicle, classified when staged): present with its events, `primeFrame(t, fx, damage)` — body-hit frames route the player's impacts to its damage and update the vehicle visuals at once (scuffs land on THAT frame's geometry: the whole buffer's crash scuffs come back, a crash 20 s before the target included), FX-window frames route events to FX + props and run `fx.update` → present the target bracket. The next normal frame updates the visuals (queued impacts → scuffs; strain seeded from the geometry). Determinism: two settled seeks to the same time give the same particles / debris (e2e); playing THROUGH a time from an earlier seek may differ slightly in continuous emitters (frame cadence).
- **main.ts replay mode:** input and discrete commands gated (`handleReplayCommands`: camera cycle, debug view; pause key = exit), spawn / quality keys blocked, `WorldFrame.timeScale` 0, skidmarks frozen while active.
- **Measured** (realistic scene in `buffer.test.ts`: player sedan + 6 awake `SEDAN_TRAFFIC` + all 198 layout props (12 awake) + 20 ghosts, 7105 nodes / 2501 awake): **24.9 KB per frame → 43.8 MB for 30 s at 60 Hz** (high budget 64 MiB; 48 MiB of chunks allocated), record **0.24–0.31 ms per recorded frame** in node after warm-up (browser EMA 0.07–0.09 ms in the arena / highway scenes at low, first keyframes ≤ 10 ms), no GC over 40 k recorded frames after the ring wrapped. Browser (SwiftShader box): arena 12.9 KB/frame, highway with traffic 16.1 KB/frame; decode 0.08–0.09 ms per frame; **settled seek 30–42 ms (arena, incl. re-playing the crash frames' damage) / 46–58 ms (highway + traffic)** incl. the 6 s FX re-run; an unsettled (drag) seek ≈ 2 decodes. Pause and resume hashes equal in the e2e (`tests/e2e/replay.spec.ts`: 114 km/h into the crash wall, one marker severity 1 at the wall, pristine 1 s before, crushed + sparks / debris at 1/4×, exit resumes).
- **Exit restores the live visual state verbatim (follow-up).** `enter` calls `ReplayVisualHooks.saveLive` before anything is presented: the player's `VehicleDamageImpl.saveState()` (every channel, strain persistence, broken / event stamps, panels, glass + crack uniforms, queued events, panel visibility), `PropRenderer.saveState()` (per-instance scuff / strain persistence / flags / written poses + the whole node texture), `TrafficController.saveReplayState()` (pool assignments + paints, each pooled visual's damage, hand-over / LOD / wheel-spin bookkeeping) and `FxSystem.saveState()` (particle pools, debris, emitter accumulators, clocks; skidmarks are frozen while replaying). `exit` hands SimClient back its live buffers (`endReplay(0)`) and restores all of it (the player's glass-shard FX are cleared). Entering presents the end frame without a settle (the visuals already show it). Tests: `damage.test.ts` / `props/index.test.ts` round trips; e2e `replay exit restores the live visual state exactly`: crash 1, wait until it left the 20 s buffer, crash 2, enter, seek to the start (crash 1's damage is there: checkpoint baseline), play / reverse / step / seek, exit → the visual-state digest equals the one saved on entry, the damage totals are identical, the screenshot differs from the pre-entry one by 0.03 / 255 on average.
- **Damage checkpoints (seek baseline).** `ReplayDriver.registerDomain({key, hitFlag, save, restore})` — main registers the player's damage (`FRAME_BODY_HIT`) and the props (`FRAME_PROP_HIT`, header word 13: a prop impact ≥ 1 N·s or prop beam break). Main reports `checkpoint(key, tick)` after the domain consumed every event up to `tick` (player: after `updateVisuals`, tick of the previous drain; props: after `props.update`, tick of this frame's drain, props scuff at drain time); a checkpoint is taken when `tick` is a recorded frame and 2 s have passed (0.25 s while that domain's hit frames are recorded). The buffer's time-window eviction never drops a frame newer than every domain's newest checkpoint (`ReplayBuffer.evictLimitTick`; space pressure still evicts), so the oldest kept checkpoint is a baseline covering damage from before the buffer. A settled seek restores each domain's newest checkpoint ≤ the target (`seed`: strain re-derives from the presented geometry; props rewrite their poses without the reset-jump clear) and re-plays that domain's hit frames after it on their own geometry, plus the FX window. Reverse playback steps the domains back through their checkpoints and hides debris (`FxSystem.setDebrisHidden`; a settled seek re-creates it on pause / direction flip). Traffic pooled visuals (re-assigned freely while replaying) still reset through the seek generation in their presented repair epochs — now applied to traffic ids only. Memory: player ≈ 45 KB and props ≈ 250 KB per checkpoint, ≈ 16–25 checkpoints per 30 s (≈ 5–8 MB).
- **Strain section:** while the beam view is shown (`ReplayDriver.recordStrains`, main sets it every live frame) non-REPEAT objects store i8 per beam (round(strain·127), −128 = broken / NaN; object table word 8); decode writes them (zeros for frames without), the slot buffers carry the strain section once any frame has one, so the beam-stress view works in replay. ≈ 1 byte per awake beam per frame.
- **Known limits:** debris does not run backwards (hidden while reversing); skidmarks overwritten by the live ring are gone from the replay too; frames are as dense as main's frame rate; the player's in-flight glass shards at entry are not restored on exit (cleared).
- **Tooling:** `playwright.config.ts` reads `E2E_PORT` (dev server port; default 5173) so parallel worktrees do not reuse each other's server. `vite.config.ts` puts `src/app/replay`, `src/ui/replay` and `src/render/cameras` into their own `replay` chunk (static imports; the app chunk had grown to 514 kB, now 473 kB; replay 41 kB).

### Decisions
- **Challenges are data.** A `ChallengeDef` names the vehicle rule (forced id or the player's choice), the spawn pose, traffic density, challenge props (`spawnProps` dynamic ids, `resetProps` on restart, despawned on exit), an optional extra collider set (`setColliders`), AI opponents, forced traction control, objectives, scoring and medal thresholds (bronze / silver / gold + the hidden 'crumple' platinum). Permanent stunt geometry lives in the LAYOUT (see "Stunt park"), so free roam has it too and the worker installs it with `groundHeightfield`.
- **Evaluation on main from live snapshots, timed by worker ticks.** `SimClient.addSnapshotListener(fn)` (additive) calls back with EVERY live snapshot as it arrives (120 Hz, independent of the render rate and of the held render loop in tests; never replay frames). `app/challenges.ts` builds one `ChallengeSample` per snapshot (COM / velocity / frame-node basis / airborne / contacts / damage / slip / crush / hubs / prop + opponent state / event-ring hits) and the PURE runtime (`src/game/challenges/runtime.ts` + `eval/*.ts`, unit-tested on synthetic samples) advances. Every clock is SIM time from snapshot ticks: run time = (finish − GO tick)/2000 with the gate crossing interpolated between the two snapshot ticks around it, so slow-mo, frame rate and the replay viewer (the worker is paused: no snapshots) never change a time. Rotations are integrated snapshot to snapshot from the chassis basis (relative rotation → axis-angle, accumulated along the body roll / pitch axes), airtime from telemetry `airborne` without body contact.
- **Ghosts = pose keyframes at 30 Hz, not re-simulation** (`GhostTrack`: f32 position + i16 quaternion, 20 B/frame, ≈ 600 B/s). A `ReplayFile` starts at `init`: re-simulating a PB in a hidden worker means re-running the whole session from boot (terrain + every command), the keyframe start stays reserved, and a file from another build is refused. Keyframes are exact for the recorded run and cost one draw to play. The PB's input slice from the P7 log (`requestReplayFile`, objectId 1, ticks relative to GO) is stored beside the ghost (`PbRecord.inputs`, ≤ 48 KB) for validation / export.
- **Opponents drive in the worker** (`setAutopilot`, below): the derby AI is a pure function of sim state, logged like any command, so the replay and the determinism hash cover it; main sends no per-frame inputs for them.
- **Restart is instant and needs no reload:** the vehicle `reset` to the spawn pose, `resetProps` of the challenge props (+ the layout props when the def touches them), opponents reset, evaluators cleared, countdown again. The countdown holds the car through the input filter (throttle allowed to rev, brake + handbrake on).
- **Personal bests** in `localStorage['crumple.challenges.v1']` (`ChallengeStore` v1: per id best score, medal, best medal ever, attempts, vehicle, build, ghost, inputs), every access in try/catch (private windows / quota: the run still works, nothing is saved).

### Protocol additions (P8, additive; SNAPSHOT_VERSION stays 1)
- `messages.ts`: main→worker `setAutopilot{objectId, mode: 'off' | 'ram', targetObjectId? (default 1), aggression? 0..1 (default 0.7), seed?}`. The worker drives that vehicle every `TRAFFIC_AI_TICKS` at the start of a tick (before phase 1, after the traffic update): pursue the target's predicted COM (lead = distance / closing speed, capped), steer by the rational atan of the local bearing, speed target 9 + 16·aggression m/s, back off and reverse 1.2–2 s when stuck (< 1 m/s for 1.5 s with throttle) or when the target is behind within 8 m; only + − × ÷ sqrt, seeded `core/rng`. 'off' zeroes the actions. Logged (`REPLAYABLE_COMMANDS`).
- `SimClient` (additive): `setAutopilot(objectId, cfg)`, `addSnapshotListener(fn) → unsubscribe`.

## P8 audio as built (P8-A, `src/audio/**`; additive)

- **No sample assets.** Every sound is synthesized by pure DSP in `src/audio/dsp/` (no DOM / WebAudio, allocation-free after construction): the same code runs in the AudioWorklet processors (`worklet/processors.ts`), in the one-shot bank worker (`bankWorker.ts`) and in node (`render.ts`; `AUDIO_WAV_DIR=<dir> npx vitest run src/audio/render.wav.test.ts` writes WAVs of every engine at idle / mid / redline / sweep / start, tyres, surfaces, wind, ambience, crashes at 1× and ¼×, every one-shot kind).
- **Loading.** `main.ts` lazy-loads `./audio` (own chunk, ≈ 47 kB) after the replay session; `?audio=0` disables it. The worklet module is `worklet/processors.ts?worker&url` passed to `audioWorklet.addModule(new URL(url, import.meta.url))` (a bare `new URL('./x.ts')` would ship untranspiled TS); the one-shot bank renders in `new Worker(new URL('./bankWorker.ts', import.meta.url))`. Without AudioWorklet the same director drives plain-node fallback voices (`io.ts`); without AudioContext the system is a no-op.
- **Engine** (`dsp/engine.ts`, profiles in `profiles.ts`, idle / redline / limiter from the vehicle's DrivetrainDef): crank phase → each cylinder fires at its slot (real firing orders: cross-plane V8 1-8-7-2-6-5-4-3 with odd cylinders on the left bank, I6 1-5-3-6-2-4 split 3+3, I4 1-3-4-2), per-slot gain / timing offsets, cycle-to-cycle variability, jitter, misfires (beater; damage adds more); sub-sample impulses → per-bank pulse shaper (fast attack, decay over `pulseDeg` crank degrees) + blowdown rasp → pipe waveguide (2L/c, open-end reflection, loop loss) → muffler low-pass opening with load → body resonance → DC block; intake Helmholtz + induction roar; valve tick, diesel knock (3 block modes), gear whine, heat-shield rattle, turbo whistle with spool lag + blow-off (coupe) / wastegate flutter (box truck) on lift-off, overrun crackle (dense right after lift-off, also on the limiter's fuel cut; upshift "brap" on the coupe), limiter bounce (11 Hz fuel cut + rpm dip), starter (motor buzz + compression chuffs, then the catch flare). `pitch` scales every frequency and time constant of a voice (Doppler × slow-mo). Two outputs: exhaust (panner behind the car, rear-facing cone) and intake + mechanical (front). Profiles: sedan 3.0 L I6 (the catalog's engine, not an I4), coupe twin-turbo V8, pickup lazy V8, box truck turbo-diesel I6, beater tired I4; traffic = the sedan's I6 as a light voice (one bank, no mechanical layer).
- **Inputs from telemetry** (`director.ts`): rpm, applied throttle, load = `engineLoad(throttle, engineTorque, peak torque)`, gear change → load × 0.2 + `shift` for the DrivetrainDef's shiftTimeS, limiter when rpm ≥ 0.985 × revLimit at throttle > 0.5, damage. Starter on every new player car (boot, swap) when parked.
- **Surface voice** (`dsp/surface.ts`, player only): squeal per axle = `squealGain(slip, load)` (silent below 1.2 m/s, full by 5.5, yields to scrub above 14) on hard ground (asphalt / rock / concrete / metal) at the profile's tyre pitch × `squealPitch`; scrub hiss; road roar ∝ `roarGain(speed)` (concrete brighter); gravel / dirt / grass rumble from `materialAt` under the COM (+ slip); body scrape from the player's NON-tyre skid events (Σ slip·load); thumps / bump-stop knocks from wheel-load jumps and tyre impacts; wind ∝ v² fading as the camera leaves the car.
- **Events → one-shots (P8 review rework: "crash noises constant while driving, like windchimes").** `events.ts` aggregates per object per frame. Player tyre contacts = within wheel radius + 0.3 m of the SEGMENT each hub midpoint sweeps from 0.15 s behind to 0.06 s ahead along the car's velocity (events lag the rendered pose; a fixed-point test misfiled tyre contacts as body hits at speed). Body impulse is weighted by the contact normal, `J·(1 − 0.85·|n_y|)`, events < 2 N·s ignored. **A vehicle crash needs** (`crashLevel`, `director.ts`): Δ telemetry damage ≥ 0.004 since the last frame, OR normal-weighted body impulse ≥ 80 N·s with one event ≥ 12 N·s, OR ≥ 2 beam breaks. Measured on recorded streams (`src/audio/fixtures/*.json.gz`): clean drives off-road / over bumps peak at Δdamage 0.001, 47 N·s weighted (311 N·s raw, all underbody-on-ground), 19 N·s single events; a 10 km/h wall tap gives 0.013 / 92 N·s. Level = max((Δd/0.05)^0.7, ((E − 60)/900)^0.6, breaks/12). A crash opens a per-object EPISODE (0.25 + 1.25·level s sim time; 0.35 s cool-down; a 1.6× bigger hit restarts it): body thud, tap (light) or crunch, a rolling crumple whose length follows the level (`crumple` variants 0.5–1.5 s), a sub boom + duck for level ≥ 0.6, a damped clang only for metal-on-metal; further deformation / breaks inside the episode add crunch grains ≥ 90 ms apart; breaks add snaps / plastic cracks, ≥ 4 breaks one debris clatter. Props: one event ≥ 8 N·s and Σ ≥ 15 N·s, ≤ every 0.25 s (barrel = drum, cone, tyre, cardboard, wood, pole, concrete). Glass only from the player's `damage.onFx` glass events. Body scrape: only a SUSTAINED body slide (skid-event occupancy EMA 0.3 s, on > 0.6 / off < 0.3). Suspension thumps (surface voice only): per-frame wheel-load jump > 7000 N or tyre impact > 20 N·s, ≥ 0.25 s apart. Regression: `recorded.test.ts` replays the fixtures through the director at 60 and 20 fps with lagged hubs — clean drives: zero crash / glass / debris one-shots, no scrape; walls: a tap at 10 km/h, crumple + boom + snaps at 60 km/h.
- **Crash synthesis** (`dsp/oneshots.ts`): low body (double low-passed noise burst + dropping 60–110 Hz thud, fast attack) + granular crumple (Poisson 0.4–6 ms noise grains through random low-Q band-passes, 300–3000 Hz, density / level decaying, in irregular waves for the rolling crumple) + creaks + plastic cracks. Metal ringing only in `clang` / `drum` / `pole`: 40–72 dense inharmonic partials, `clang` T30 ≈ 0.13 s. Glass: crunchy broadband grain burst + a few short fragment ticks (no sine partials). Measured: crash centroid 280–390 Hz, max narrow spectral peak ≤ 6.6 dB, no sustained tonal energy after 150 ms.
- **Traffic:** ≤ 4 awake cars (2 on low) with light engine worklet voices driven by their telemetry, ≤ 4 ghosts (2 on low) with pooled pass-by voices (engine hum + tyre roar, plain nodes); nearest first, Doppler computed manually (`dopplerFactor`, source velocity = record speed × forward × rate, listener velocity from camera motion) and applied through `pitch`.
- **Mix** (`mix.ts`): engine / tyres / ambience → duck → world (+ one-shots) → slow-mo low-pass → dead-man gain → master → compressor → limiter; reverb send (synthesized IR) from engine + one-shots; UI bus beside the world chain. The dead-man gain is re-armed each update (≤ every 0.1 s) and fades the world 0.28 s after the frame loop stops calling (pause menu, showroom, held loop, hidden tab) — no pause hook in main. Player car panners HRTF on medium+, equal-power elsewhere; inverse distance model.
- **Time:** rate = live timescale or replay `playing ? speed : 0`; rate 0 silences the world; below 1× every voice is pitched by `slowMoPitch(rate)` = rate^¾ clamped [0.32, 1.35], `slowMoLowpass` closes (≈ 2.4 kHz at ¼×), reverb rises; crash cam (`replaySession.crashCam.phase === 'playing'`): low-pass ≤ 1.5 kHz, reverb 0.42, a whoosh on the UI bus. Replay voices follow SimClient's presented telemetry; one-shots only while playing FORWARD; a replay seek / enter / exit drops queued events and stops ringing one-shots.
- **Settings** (`crumple.settings.v1`, additive fields): `volume` (master), `engineVolume`, `effectsVolume`, `ambienceVolume`, `muted` (suspends the context); pause menu "Sound" + four meter rows.
- **Autoplay:** the context resumes on the first pointerdown / keydown / touchstart; a "Click to enable sound" pill (bottom left) shows if it is still suspended 2.5 s after the system loaded.
- **Ambience** (`dsp/ambience.ts`, `zones.ts`): birds (three singers, three species), breeze, golden-hour crickets, lake lapping near the shore; birds / crickets fade out in the arena and at altitude, the breeze rises with altitude.
- **Debug / perf:** `__crumple.audio` = `AudioDebug` (state, worklet, voices, one-shots played, bank ready, update ms EMA / max, last crash, engine and world state, `resume()`); `prof.lap('audio')` in the perf overlay. Measured: 0.13 ms mean per frame in Chromium for the player car (HRTF) + 4 ghost + awake traffic voices (`tests/e2e/audio.spec.ts` bench, timer resolution 0.1 ms). Allocation: no per-frame objects; a few doubles boxed across call boundaries remain (≈ 80 B/frame in node: ≤ 6 minor GCs over 300 k frames, i.e. one per ~45 min at 60 fps; `director.test.ts`).

## Spawn placement + settle (additive; fixes "spawning at a new spawn point damages the car and breaks the windows")

- **Root cause (two parts).** (1) Main-side: `SimClient.interpolate` lerped every object between the two held snapshots, also across a `reset` / respawn. A teleport to a spawn with another heading drew one or more frames of a squeezed body (a 180° turn passes through a point at t = ½); the damage visuals measured those frames as plastic strain and glass strain above `crackStrain` / `shatterStrain` on the freshly repaired car (repair epoch already new), so the panes cracked / shattered and the body showed crumple shading while telemetry damage stayed 0 (e2e before the fix: summit Σcrack 2.7, town Σcrack 3.0 + max strain 0.08). (2) Sim-side: placement was yaw-only, so on a slope (Hollow Creek trailhead ≈ 10°) one axle started up to ~0.8 m above the ground and the drop yielded beams (box truck: 66 beams up to 2.6 %, coupe: a rear-glass beam broke, glass strain 4.1 %), and every box-truck spawn yielded 2 beams from the 6 cm drop + suspension preload transient.
- **Interpolation:** `interpolate` / `objectNode` take the current positions when an object's repair epoch differs between the two snapshots. The worker continues an objectId's epoch across `despawn` + `spawn*` of the same id (`retiredEpochs`: respawn = last epoch + 1), so a showroom DRIVE with the same body (same node count) is never interpolated from the old car either.
- **Placement (`src/app/spawn.ts`, the one API for every vehicle spawn incl. challenges' `spawnTransform`):** `placeOnGround(rest, ground, x, z, yaw, drop?)` fits a least-squares ground plane under the whole rest-pose footprint (`groundSlopes`, 5 × 9 samples), tilts the rig's up axis to its normal (≤ `SPAWN_MAX_TILT_RAD` 30°; heading kept), then lifts it so the lowest node over the ground under ITS OWN XZ clears it by `drop` (default 6 cm). Main (`clearSpawnAt`) additionally moves a spawn / teleport / DRIVE pose back (then forward) along the heading until it clears every other object of the latest snapshot (props where they lie now, the cube, awake traffic; `repairSpot` with their bounding boxes); F keeps clearing the props' spawn boxes.
- **Settle window (protocol additive):** `spawnVehicle.settle?` and `reset.settle?` (sim s, clamped to `SPAWN_SETTLE_MAX_S` 2, rounded to ticks; omitted / 0 = none). ## Feel pass — jitter + body stiffness (additive; supersedes the protocol's "main interpolates between the last two snapshots")

### Presentation clock (`src/app/renderClock.ts`, `SimClient.renderTime / interpolate / objectNode / readTrafficAgents`)
- **Root cause (measured, `src/app/presentation.harness.ts`):** the old render clock restarted at each snapshot arrival (`prev.simTime + span·(now − arrival)/smoothed interval`, clamped). Worker wakes are setTimeout-paced (≥ 4 ms clamp) plus step CPU, so arrivals jitter by several ms and snapshot spans alternate 1–2 ticks; the clock snapped every arrival and held on late ones. A 30 m/s probe's per-frame step was uneven by 46–149 mm RMS (max 0.11–0.44 m) at 60 / 120 / 144 Hz.
- **Now:** `RenderClock` advances by wall time × the snapshot's `timeScale` and steers its RATE (±8 %, ±25 % when far behind, slewed) so the lowest lead (newest snapshot time − render time just before an arrival, fast-down / slow-up filtered) settles at 1.5 ms: the render time trails the newest snapshot by ≈ one snapshot interval + arrival jitter (mean lag 8–13 ms). Late data → linear extrapolation ≤ ½ interval, then hold. Re-sync on lead > 0.1 s, time going backwards, or replay exit. Measured after: 0.15–0.9 mm RMS, ≤ 3.7 mm max per frame (`presentation.test.ts` asserts < 1.5 / < 5 mm at 60 / 120 / 144 Hz).
- **Node history:** main still holds ≤ 2 snapshot BUFFERS (pool unchanged); it copies each live snapshot's node positions, object table and traffic records into a 6-entry ring (`NodeHistory`) and interpolates the delayed render time between the bracketing pair, in the newest snapshot's layout. Telemetry, events, strains and broken bits still come from the newest snapshot. Replay presentation is unchanged (prev/cur pair at the playhead).
- `renderTime()` advances the clock on every call: call it once per frame (`main.ts` reuses the value for nodes, traffic, FX and props).

### Rigid shell clusters (`src/sim/vehicle/shellDefs.ts` pure defs, `shell.ts` worker kernel; additive `VehicleDef.shell`, `CompiledVehicle.shell`, `VehicleRuntime.shell`)
- **Root cause of the "jello" bodies (measured, `bodyflex.ts`):** with every node at the ω·dt budget, beams are 1–4e5 N/m on 5–13 kg nodes; the lattice's global modes sit ~20× below the node-local frequency. Sedan before: torsion 1.8 kN·m/deg (real 15–40), first free-free torsion / bending modes 3.5 / 4.5 Hz, extremity deflection 17 mm launch, 7 mm brake, 13 mm at 1 g, 97 mm over a 8 cm kerb at 50 km/h, wobble decaying over ~0.5 s; the same on every vehicle (coupe 1.3, beater 1.2, traffic 1.35, pickup 0.58, box truck 1.0 kN·m/deg). In crashes the cabin rippled: 50 km/h frontal 4.8 cm permanent / 30 cm peak cell distortion, 17 mm door-skin ripple; 100 km/h 27 / 47 cm, 80 mm.
- **Model (shape matching, implicit):** per cluster, every tick after all force passes and before integration: weighted COM c, predicted velocities v* = v + (F/m + g)·dt, best-fit rotation R = polar(Σ w m (x − c)(r − r̄)ᵀ) (scaled Newton, ≤ 12 iterations), spin ω = I⁻¹ Σ w m (x − c) × (v* − v_c); per node goal g = c + R(r − r̄), goal velocity vg = v_c + ω × (x − c), Δv = [β(vg − v*) − k·dt·(x − g)]/(1 + β), β = c_d·dt + k·dt², F += w m Δv/dt. k = (2π·60 Hz)², c_d = 2·0.7·ω (box truck box 60 Hz). Backward-Euler with the goal held for the tick: unconditionally stable, so it is not an explicit spring and adds nothing to the per-node ω·dt budget (beams keep `sqrt(Σk/m)·dt ≤ 0.5`, masses unchanged). Linear + angular momentum exact (Procrustes optimum; damping targets the cluster's own rigid field). Only + − × ÷ sqrt, fixed order, zero allocation.
- **Tiers (`ShellZone`, first match wins; `shellLayout` builds front / rear / cell / firewall):** crumple zones (front: bumper → firewall stations, hood, front subframe; rear likewise) = weak YIELD bond (4 mm) released WHOLE by an impact (≥ 4 m/s relative to the rigid motion at any node, or 5 cm): the crush then runs on the beams alone, exactly as tuned. Safety cell (A/B/C pillars, sills, roof rails, floor, doors) = YIELD at 3 cm (perfectly plastic: the rest shape flows, no spring-back) with a local release at 5–9 m/s (an impact AT the node: pole, intrusion). Firewall ring = released whole at 4 cm / 3 m/s (hard frontals: the windscreen frame strains, glass breaks). A yielding node pressed into a ground / collider contact past 1 cm is released (the bond is stronger than the contact penalty: it must never drag a node through a pole). Box-truck box: released whole at 2 cm / 4 m/s. Beater: the whole body releases at 1 cm / 2 m/s (it folds like paper, no cell). Pickup cab: `cellWhole` (released whole at 2 cm / 2 m/s); frame rails under the cab yield at 5 mm.
- **Clusters per vehicle:** one per car body (sedan, coupe, beater, traffic: groups body + hood + subframe; pickup: frame + cab + bed + tailgate). Box truck: cab and box are separate clusters; its ladder frame stays a beam lattice (frame torsion drives the J-turn / ramp-steer rollover targets; per-rail and whole-frame clusters both broke them).
- **Recapture:** after a release, once the released nodes have moved < 0.08 m/s relative to the rigid motion for 1 s, the current (crushed) shape becomes the rest shape and every node whose incident beams are intact rejoins (a crashed car drives on stiff). `reset` restores the original shape; `recover` keeps it.
- **Measured after** (`bodyflex.test.ts`, one case per vehicle; crash numbers in `crash.test.ts`): sedan torsion 21.2 kN·m/deg, coupe 24.1, pickup 7.0 (its light spring-hanger nodes' anchor beams dominate the mount compliance; short of 15), cluster modes 55–60 Hz (box truck bodies 60 Hz, frame ~9 Hz); extremity deflection ≤ 0.3 mm launch / brake / 0.7–1 g / kerb on every car (box truck cab + box ≤ 1.3 mm), kerb wobble gone within one sample (truck bodies keep ~0.5–1 mm of forced frame motion for 1.7 s); 0.5 m spawn drop and kerb strikes break no beam (glass included), release no node. Sedan crashes: 50 km/h crush 47.7 cm (was 53), spring-back 24 %, cell 1.5 cm final / 3.9 peak, ripple 2.7 mm; 100 km/h cell 12.8 / 38 cm, 44 mm; pole door 31 cm, cell 2.4 cm outside the dent, 0.3 mm ripple.
- **Def retunes it needed** (each documented at the constant): sedan `REAR_BAY_FACTOR` 10 → 8 (spring-back), pickup `FRONT_BRUSH` 4.5e4 → 3.3e4 (R40 0.947 → 0.91 g) and hood `latchBreak` 5 → 4 kN, beater `DOOR_YIELD_STRAIN` 0.025 → 0.015 (pole ratio vs the sedan). Test thresholds adjusted with reasons in place: rollover small-roll reading > 4° (was 5°: the frame nodes no longer flex), parked-on-a-grade jitter ratio floor 2 cm/s (the parked body now sits at a few mm/s instead of 0.14 m/s), autopilot hit sampled every 50 ms.

### Drivetrain feel (`src/sim/vehicle/drivetrain.ts`; state additive on `DrivetrainStateEx`, no protocol change)
- **Root causes of the "jittery acceleration" (measured, `bodyflex.ts` launch trace, body fore-aft acceleration):** (1) every upshift opened the clutch for half the shift time (zero drive torque: the car pitched and the tyres' wound-up carcass snapped back, −5 m/s²) and re-closed it on an engine ~2000 rpm above the new gear (its flywheel dumped into the tyres: a 2× torque spike, wheelspin); (2) the proportional traction control (0.5 per m/s, 20 / 150 ms) limit-cycled at ~6 Hz with the tyre's stick-slip (sawtooth throttle, ±2–3 m/s² surging); (3) the auto-clutch closes in ~50 ms, so a full-throttle launch dumped ~1.8× the traction torque into the tyres (slip ratio ≈ 11, then ~1.5 s of surging); on the beater (no TC) a 21 Hz wheel hop.
- **Power-on upshift** (clutch-to-clutch, like a torque-converter automatic or a DCT): the new ratio is selected at once; for the inertia phase the clutch slips at the torque that keeps the WHEEL torque where it was (clutch torque × old / new ratio, never less than the engine torque + Ie·600 rad/s², the margin fading with the slip) while the throttle is retarded to 0.3 and returns as the slip falls through 60 rad/s; it ends when the slip is < 3 rad/s (≤ 1 s). Downshifts keep the open-clutch rev-matched shift.
- **Traction control** is PI on the low-passed excess driven-wheel speed (0.15 per m/s + ∫1.2, integral clamped [0, 1], 30 / 60 ms attack / release). Below 2.5× idle (clutch still slipping) the cut opens the clutch instead of the throttle (blended over 1–1.3× that floor).
- **Launch control** (TC on, or always on a car without TC; TC switched off = raw launches and burnouts): below 3–7 m/s road speed (undriven wheels, smooth fade) the clutch passes at most 0.9 × the driven tyres' μ·load·r (load low-passed 0.4 s: an instantaneous limit fed back through squat at ~5 Hz) and the throttle holds the engine near 4× idle. Off when no driven tyre touches the ground.
- **Measured** (`launchFeel.test.ts`, full-throttle standing start through 2–4 upshifts, default assists; band RMS of the body's fore-aft acceleration, ratio to the mean): sedan 2–8 Hz 0.80 → 0.18 m/s² (0.19 → 0.04), 8–25 Hz 0.72 → 0.24 (0.17 → 0.055); coupe 0.91 → 0.24, 1.10 → 0.47; pickup 0.77 → 0.17, 0.39 → 0.26; beater 0.43 → 0.24, 1.04 → 0.30; traffic sedan 0.72 → 0.17, 0.75 → 0.49; box truck 0.57 → 0.42, 0.19 → 0.10. Bounds: 2–8 and 8–25 Hz < 0.15 × mean (beater 8–25 < 0.17; truck 2–8 < 0.3: a ≈ 5 Hz chassis / rear-axle mode rings ≈ 1 s after its launch with a smooth drive torque, open). The 25–200 Hz band (tyre polygon, ≤ 0.4 m/s²) is below what the chase camera shows.
- **Retunes:** beater `autoShiftUpRpm` 5600 → 5000 (seamless upshifts made it 0–100 in 10.6 s; now ≈ 12 s, target 11–14). Tests: "cuts torque during a shift" became the power-on upshift test (wheel torque held within 0.8–1.3× through the inertia phase, synchronised after) + a downshift test; the sedan's full-torque axle test runs with TC off (launch control would hold the clutch at the traction torque).

### Crash settling (`shellDefs.ts` RECAPTURE_IMPACT_*; `crashRing.test.ts`)
- **Measured** (`crash.ts` `crushSettle`, rigid-wall frontal, crush sampled every 5 ms): after the peak the released crumple zone and cell were a loose beam mechanism until the 1 s calm recapture, so the crushed front kept swinging (50 km/h sedan ±2 cm at ~4 Hz to 0.6 s; 100 km/h sedan / traffic 3–5 cm still 0.5 s after the peak). An energy audit of the 50 / 100 km/h frontals (stored beam energy by class, shell-bond energy, contact penetration energy, internal KE) puts the rebound in (1) members loaded near yield at their stability-capped k (1–20 % elastic strain at yield: crumple-zone / cell interface, subframe → sill, and at 100 km/h the speed-released cell rails, 10–25 cm elastic), (2) the engine block's non-yielding beams (12–15 kJ at 100 km/h), (3) the wheel / tyre / hub assemblies squeezed between wall and body.
- **Post-impact set:** once no shell node has newly released for RECAPTURE_IMPACT_S (0.15 s) and the released nodes' RMS speed relative to the rigid motion is below 0.5 m/s, or at the latest RECAPTURE_IMPACT_MAX_S (0.3 s) after the last new release, the shell is recaptured in its crushed shape (as the 1 s calm recapture: broken-off nodes stay out, a new impact releases again).
- **After** (overshoot below the final crush / ring 0.5 s after the peak): sedan 50 2.4 → 1.1 cm / 1.4 → 0.0 cm (0.7 cm at 0.25 s); coupe 50 0.7 cm; traffic 50 1.4 → 0.7 cm, 100 5.4 → 1.7 cm; crush depths, pole, offset and cell results unchanged.
- **Not shipped (open): the rebound.** Unchanged: sedan 21 / 23 %, coupe 21 / 22 %, traffic 21 / 15 %, pickup 10 / 8 %, beater 13 / 8 %, box truck 15 / 5 % (50 / 100 km/h; old contract 1–4 m/s at 50). Tried: (a) unloading hysteresis for yielded members (rest length follows a member springing back, during the impact only): sedan 50 → 14 %, 100 → 11 %, but it changed the wrap of the pickup's A-pillar round the side pole enough to fail the pull-through check at ~2 s, and without the impact gating it left plastic sets after hard driving; (b) the engine / gearbox block as a rigid 200 Hz cluster: 100 km/h rebound 23 → 16 %, but the sharper pulse folded the sedan's trunk in the 100 km/h frontal (side-view frames) and tore the box truck's box mounts past the limit; (c) holding the cell (no speed release): more rebound; (d) heavier collider contact damping: no effect.

### Open structure items (measured, not shipped)
- **Box-truck ladder frame.** Rail-truss bending relative to its own rigid fit (`scratch` harness, 100 → 0 km/h full brake): 3 cm in the middle while braking, 6–12 cm at the stop shunt; the frame hinges between the cab (f3–f5) and the box (f6–f13), whose floor runners stay out of the box cluster. Tried: one whole-frame cluster (30 / 60 Hz: 4.3 / 1.7 mm, but the front inside wheel lifts at 0.40 g, target ≥ 0.45); per-rail clusters f1–f13 with their spring towers (60 Hz: 1.7 mm, lift 0.43 g; 25 Hz: 9 mm, lift 0.46 g, rolls over, J-turn / steady / handling all pass) — but as a held cluster the rail backs the side underride guards, so the "sedan into the box side keeps a ≥ 15 cm dent" target drops to 7–14 cm, and any release threshold that lets a side hit through (≤ 8 mm, or ≥ 1 m/s) also releases at a 50 km/h kerb or under the static frame load. Needs a structural change (deeper / heavier rails within the 6.5 t, or a guard load path that does not run through the rail) rather than a cluster.
- **Pickup torsion** 7.0 kN·m/deg (target 15–40): raising the shell frequency 60 → 120 → 240 Hz gives only 8.3 → 8.8, so the compliance is not the cluster bond; the corner mounts are light suspension pivots (4.4–8.5 kg) in the crumple tiers, whose perfectly plastic 4 mm yield bond (force m·k·lo ≈ 2.5 kN) flows under the torsion load. Not fixed: making those tiers stiffer changes the tuned frontal / rear crush.

### Signals (`src/world/signals.ts`) — for the traffic AI agent
- One `SignalPlan` per `control: 'signal'` junction (layout order) = the index `RoutePath.signal.plan` uses. Legs = the junction's approaches (road id + side, the route network's leg convention: side −1 = the road part at smaller s) with their stop-line point, approach direction and half width. Two fixed-time phases: phase 0 = the through road's legs (green 24 s), phase 1 = the rest (14 s); amber 3.5 s, all-red 1.5 s; per-plan offset = FNV(junction id) mod cycle.
- **Time base = sim ticks (2000 Hz, `SIGNAL_TICK_HZ`)**, integer arithmetic: `signalAspect(plan, leg, tick) → 'green' | 'amber' | 'red'`, `ticksToGreen(plan, leg, tick)`. The worker AI passes its tick; main's signal heads pass the presented sim time × 2000, so both always agree and replays reproduce them.
- **AI rule:** enter a connector with `signal` only on green; on amber stop if the stop line is reachable at ≤ 3 m/s²; red = hold at the leg's stop line / lane end. `stop` connectors: come to rest before entering, then the normal yield rules. Signalled junctions: `ringNorth`, `ringSouth`, `ixNorth`, `ixSouth`, `hwyWestCross`, `hwyEastArena`; stop control: `ringWest`, `ringEast`, `townNorth`, `millJunction`, `townSouthGate`, `northFork`.

### Physics amendments
- **Reaction couples** (amends "No body reaction couple in P2"): a brake torque reacts on its upright (`wheels.ts applyUprightReaction`: on `WheelRuntime.reactNodes` — the `attach` nodes ≥ 6 cm off the axle, else the far ends of the hub-link beams — `F_j = −τ·(s × ρ_j)/Σ|ρ|²`, the hubs take −ΣF split `WheelDef.caliperInboard` : 1 − it between hubI / hubO); it fades in over 0.3–1 m/s of hub speed (at rest the parking clamp is a numerical holding device). Drive torque reacts on the body (`DrivetrainDef.driveReaction` 'body', default: a pure couple spread as the rigid-body angular acceleration of all body nodes, `runtime.ts applyDriveReaction`) or on the upright ('axle': live axles, the box truck). Rolling resistance and the tyre model's loss correction are ground moments: no reaction. Why: every brake applied an external torque to the car; the braking load transfer was m·a·(h − r)/L — sedan 1305 N/g vs m·g·h/L = 2473 N/g; after: 2292 N/g (93 %, realism test 85–115 %).
- **Tread friction** (`ground.ts`, tread nodes only): the brush takes the tread's lateral friction first; the node stick's lateral share (along the brush axis â) is capped at `|â|·μN − F_brush`, `|â|` = the tyre's μ_y/μ_x (`applyTreadBrush` writes `treadAx` = â·latMu). Before, the stick's lateral share came from the quadrature remainder and brush + stick reached 1.24 μN; with no lateral stick at all a parked truck's heavy tread nodes fluttered (2.5 m/s).
- **Tyre model** (`tyre.ts`, new): per wheel per tick, before the brush and the ground pass, the tread nodes' μ = base · f_load · f_slip — load sensitivity f = 1 − ls·(F̄z/Fz0 − 1) (F̄z low-passed 30 ms, Fz0 = `tyreDesignLoad` or the car's weight / wheels), sliding fall-off f = 1 − (1 − r)·smoothstep(σ_peak, σ_slide, σ) on the rigid wheel's combined slip σ = |slip velocity| / max(V, 3 m/s). Rolling-loss correction: `WheelDef.rollingLossComp` (per unit load every 20 km/h of tread speed) fed back as an axle torque; calibrated per car by coasting (0.85 × the lower of each bin and its neighbours' mean, so a coasting car is never propelled). WHY: the 12/10-ray tread polygon's vibration loss is a discretisation artefact (C_rr 0.07 at 120 km/h, 0.16 at 160 vs a real 0.01·(1 + V/160)).
- **Brake system** (`brakes.ts`, new; runs after `stepDrivetrain`, replaces the service part of `WheelRuntime.brakeTorque`): caliper pressure per wheel (pedal → pressure lag 30 ms); **ABS** (`BrakesDef.abs`): reference speed from the IMU (ESC cars: body speed along the heading) or the wheels (ABS-only: fastest wheel inside a μ·g ramp), per wheel BUILD → DUMP (12 ms valve pulses: slip > 0.22 or wheel decel > 35 m/s² past 0.11 slip) → HOLD (20 ms checks) → BUILD (fast to 0.8 × the lock pressure, then a 2/s staircase), off below 2 m/s; **EBD**: a rear wheel's pressure does not rise while it slips 3 % more than the front axle; **ESC** (`BrakesDef.esc`): yaw rate (frame heading, 20 ms filter) vs the bicycle-model reference v·δ/(L + K·v²) (K 0.0021 rad per m/s²) clipped to the measured lateral g + 0.12, oversteer (yaw excess beyond 0.05 rad/s + 15 %, or a sideslip > 4° growing against the rotation) brakes the outer front (gain 3, ≤ 0.7), understeer gently the inner rear (≤ 0.25), with an engine torque cut (`DrivetrainStateEx.escCut`, ≤ 0.6). Handbrake bypasses ABS. Fitted: sedan, coupe, pickup, traffic sedan ABS + ESC; box truck ABS; beater ABS (a 1990s compact; no TC, no ESC).
- **Dampers** (`dampers.ts`, new; vehicle pre-step after the drive reaction): per shock beam the correction F(v) − d·v along the beam, so the damper force is F(v): bump / rebound low-speed rates as fractions of the def's calibrated d (default 0.5 / 1.3, i.e. rebound 2.6 : 1), digressive past a 0.1 m/s piston-speed knee (high-speed slope 0.5×), faded out between 1.2 and 2 m/s (crash speeds keep the linear d the crash tests were tuned with). Per axle via `VehicleDef.dampers` (`true` = defaults); a shock beam belongs to the axle of the nearest wheel hub. Fitted: sedan, pickup, beater, traffic sedan; coupe and box truck keep linear dampers (see R-PHYS ↔ R-CRASH; the truck's d sits at its light axle nodes' ω·dt budget and jittered parked). Sedan over a 4 cm × 0.4 m cleat at 50 km/h: peak body acceleration 0.28 → 0.22 g; body bounce ζ (full-period decrement) 0.38 / 0.32 → 0.36 / 0.30 front / rear.
- **Brake heat + fade** (`brakeHeat.ts`, new): per braked wheel a lumped disc, m·c·dT/dt = 0.9·(−τ_applied·ω) − hA(v)·(T − 25 °C) − εσA(T⁴ − T_amb⁴); hA from cooling time constants 600 s parked / 100 s at 100 km/h (solid discs 0.6× the speed part); pad μ factor `BRAKE_FADE` (0.95 cold, 1.0 at 150–350 °C, 0.85 at 500, 0.74 at 600, 0.52 at 800 °C) scales the caliper torque (`BrakeSystemState.fade`). `WheelDef.brakeDiscMass` (default brake torque / 300 N·m per kg), `brakeDiscVented` (default front). Sedan: 15 back-to-back ABS stops from 100 km/h take the front discs 62 → 514 °C; a fixed 0.3 pedal decelerates 5.85 → 5.28 m/s² hot (−10 %); the ABS stop stays 39.5–40.4 m (the caliper still out-torques the tyre). Disc temperatures are R-PHYS state, not yet in telemetry (open).
- **Static collider overflow** (R-WORLD ask): more than `COLLIDER_MAX_CANDIDATES` candidates truncates to the lowest indices (deterministic) and counts `ColliderWorld.overflow`; never throws.

### Eye adaptation (`post/exposure.ts`) — amends the post pipeline
`RenderPass → N8AO → Metering → [Sanitize] → EffectPass(SMAA, Bloom, Exposure, ACES, Vignette) → [LensRain]`. Metering = 32×18 float grid of log luminance (16 taps per cell) read back asynchronously every 3 frames; centre-weighted log average (sky band × 0.55) → target factor (`EXPOSURE_REF_LUM` 0.13 → 1, partial adaptation k 0.78, range 0.35–4.5), eased in EV (τ 0.45 s toward light, 1.8 s toward dark); bloom threshold ÷ factor; Purkinje shift (rod desaturation + blue) when adapted to the dark, fading out where cones see (headlights stay coloured). `PostStack.exposure?: {value, snap(), target?, set?(value, target?)}` (an env change snaps it; replay saves the adaptation with the live visual state and `set`s it back on exit); renderer.toneMappingExposure stays photo mode's EV. Async readbacks go through `render/readback.ts` `readPixelsAsync` (three r185 leaves its PIXEL_PACK_BUFFER bound while it waits, which made every synchronous readPixels meanwhile fail — dev pages, e2e samplers).

### Clouds (`lighting/clouds.ts`)
Cloud drift follows `env.clock` (seconds of live play: frozen while paused / replaying, so a replay exit restores the same sky). Raymarched cumulus layer 1.4–2.6 km on the planet's curvature; 96³ Perlin–Worley noise generated on the GPU once (3D render target, one draw per slice); marched into an upper-hemisphere panorama (sqrt elevation mapping) every `period` frames; lighting: Beer + powder, two-lobe HG, light march toward the key light, sky / ground ambient, aerial fade; composited by the dome and the IBL; cloud-shadow map 256² over 4 km every 2·period frames. `CLOUD_QUALITY` low 384×96 / 6 steps / no light steps (flat 2D layer) … ultra 2048×512 / 28 / 5.

### Rain + spray (`fx/rain.ts`, `fx/index.ts`, `post/lensRain.ts`)
- Rain streaks: one instanced draw (`RAIN_DROPS` 1.5k / 4k / 7k / 14k at full rain), a box that wraps around the camera, streaks along the drop motion relative to the camera, lit by ambient + key + the light grid + the player's beam cone (forward scattering: drops glow in the headlights). Not in shadows or the planar reflection.
- `FxSystem.setWeather?({wetness, rain})` (additive): tyres on sealed surfaces (`wetSurface`) lift a mist of road water (K_HAZE puffs, ∝ wetness × (speed − 5 m/s), `WET_SPRAY_RATE`).
- Lens drops (`PostStack.setLensRain?(amount, t)`): own EffectPass at the end, only while it rains on the chase camera (never in replay / photo / pinned shots).

### Bundle
`render/lighting/lazy.ts` = one lazy chunk (lighting stack, sky, clouds, env GLSL, light grid, night lights, headlights, rain; ≈ 67 kB): main imports it dynamically at boot (the stack was already async) and only types statically; the app chunk grew ≈ 5 kB for the environment / weather work (settings, env uniforms, exposure, lens rain).

### Tools
`tools/gfx-shots.mjs` (+ `tools/vite.frozen.config.mjs`: no HMR reloads mid-shot): scripted screenshots of the time-of-day / weather / night scenes (`ONLY=…`, `W`, `H`, `Q`, `OUT`, `TAG`). `dev/nightlab.html`: one streetlight on a plane for the night-light path.

## R-RIG — high-density vehicle rigs (additive)

Ownership: `src/sim/rig/gen/**` (generator), `src/sim/vehicle/defs/hd/**` (HD variants, generated skin data, variant registry), `src/render/vehicle/defs/hd/**` (HD visuals), `tools/rig-*` (skin extraction, offline crash images). The standard rigs are untouched (R-CRASH / R-PHYS edit them); an HD variant is GENERATED from the current standard def at load, so their retunes flow into it.

### Physics quality ⇄ rig variant (the seam with R-CORE's quality setting)
- `PhysicsQuality` = `'standard' | 'high' | 'ultra'` and `PHYSICS_QUALITY_BUDGETS` (player beams / nodes per tier: 3500 / 1024, 8000 / 2048, 14000 / 3072) live in the LIGHT module `src/sim/vehicle/defs/hd/variants.ts` (no rig data; main and worker may import it). `loadVehicleVariant(car, quality, standard)` → `VehicleVariant{car, quality (delivered), def, probes, report?, collision?, skinNodes?}`; each car's HD rigs are a separate dynamic-import chunk generated on first use; a car without the asked tier falls back to the next lower one (`variantTiers(car)` for UI). R-CORE owns the setting (persistence, UI, which tier the worker kernel can afford); a variant is just a `VehicleDef`, so `spawnVehicle` / replay / traffic need no protocol change (the replay log carries the def it ran).
- Render: `vehicleVisualSync(car, quality)` (`src/render/vehicle/defs/hd/index.ts`) = the standard visual for 'standard', else the visual re-pointed at the HD rig (`repoint.ts`): every sampled exterior panel binds ONLY to its own sheet (`k_<panel>_*`), small parts mounted on a sheet follow it (`<CAR>_MOUNTED`), everything else binds to the backbone exactly as on the standard car; LOD1 / LOD2 + door-card followers registered (`setVisualExtras`). Zero dropped panels at every LOD is a test per car.
- Sync registries for tests / tools: `src/sim/vehicle/defs/hd/index.ts` (`vehicleVariantSync`, `STANDARD_VARIANTS`) — never imported by game code.
- **Collision triangles** (R-CORE node-vs-triangle): `VehicleVariant.collision` = `CollisionTriangle{a, b, c}` (body node ids, CCW seen from outside) over every sheet. Provisional shape until R-CORE freezes its declaration format; the generator emits whatever R-CORE specifies from the same sheet triangles.

### Generator (`refineVehicle(base, {name, skins, skinSpec})`, `src/sim/rig/gen/refine.ts`)
- **Backbone kept bit for bit:** every standard node id + rest position, wheels, drivetrain, brakes, aero, dampers, steering, frame nodes, shock / hydro beams and every beam touching a non-shell node (subframe, knuckle, engine, axle). Harness probes, R-PHYS's hardpoints / rates and the shell zones carry over; new nodes / beams are appended (standard indices unchanged).
- **Sheet-metal skins** (`skin.ts`): `tools/rig-skins.mjs` samples each car's lofted render panels (outer sheet only: triangles facing out of a super-ellipsoid fitted to the body) into a grid at the tier's pitch (`SKIN_TIERS`: high 0.15 m, ultra 0.11 m) → generated data `src/sim/vehicle/defs/hd/skins/<car>.<tier>.ts` (the sim never imports render; `src/render/vehicle/defs/hd/<car>.test.ts` fails if the committed data drifts > 5 mm off the render surface — re-run the tool). Per sheet: membrane beams (grid edges + both quad diagonals), bending beams (every second node along each grid line: the crowned panels dent locally and keep their crown), seams to the nodes the render panel binds to (`SeamKind` weld / hem / bolt / glue: every boundary node seamed to its nearest frame node, every second one to two; elastic, tearing at 45 / 60 / 80 / 30 % strain, load sheds to the neighbours so a seam unzips as a group), standoffs to the inner structure (door inner panel, hood / deck-lid frames, roof bows). Real areal mass (`materials.ts` grades: BH220 0.7–0.75 mm outer panels, DC04, HSLA340, DP600, boron, AL6016, PP/EPDM 2.5–3 mm fascias); sheets yield at 1.5 % strain (dents set) and tear at 30× that force.
- **Mass:** the sheets' real mass is taken from the backbone shell nodes whose beams are all shell-to-shell (`s_i = s0 + a·Δz + c·Δy + e·Δx`, solved so total mass and CG x / y / z equal the standard rig's exactly).
- **Stability by construction:** sheet beams take the sheet node's budget at ω·dt 0.47 (group `body`, MINIMASS limit 0.495); a backbone node that lost mass or gained seams has its scalable beams (normal / support / bounded between shell nodes) scaled by `f = (s·Σk − Σk_fixed − Σk_seam)/Σk_scalable` with their damping, so no node's Σk/m grows; deform / break FORCES are kept. (Σd/m)·dt ≤ 0.9 on sheet nodes, seams' damping trimmed where a frame node would pass the backbone's 0.95. Result: MINIMASS drift 0, validator clean at the tier budget.
- **Why stiffness is budget-limited (not real):** at dt = 1/2000 s explicit integration caps a node's Σk/m at (0.5/dt)²; steel's wave speed at 10–15 cm pitch would need ~50× the node mass. Mass, yield / crush forces and the seams are real; elastic stiffness takes the budget (shared by weight); the shell cluster (shell.ts) supplies the body's global stiffness while driving.

### Harness amendment
- `crash.ts`, `handling.ts`, `bodyflex.ts` engine capacity 2048 / 8192 → 4096 / 16384 nodes / beams (HD rigs up to ~2000 nodes / ~12000 beams). No other harness change: every harness takes the variant's def + probes.

## R-CORE — solver + contact core (WASM kernel, contacts, physics quality)

Ownership: `src/sim/engine.ts` (the step / solver parts), `src/sim/{beams,integrator,state,kernel}.ts`, `src/sim/wasm/**` (C source, built binaries, glue), `src/sim/collision/**` except the tyre-surface friction (R-TYRE: the tread branch of `ground.ts`, `tyre.ts` / `wheels.ts`), `tools/build-wasm.sh`, `tools/bench-physics.mjs` + `tools/physbench/**`, the physics-quality scaffold (`src/app/physicsQuality.ts`). Contract files (change only via this doc): `src/sim/kernel.ts`, `src/sim/rig/types.ts` (the R-CORE additions), `src/protocol/messages.ts` (the R-CORE block), `src/protocol/replay.ts` (`setSolver`), `src/world/types.ts` (`ColliderMesh`).

### Kernel seam (`src/sim/kernel.ts`, landed)
- `KernelKind` `'js' | 'wasm' | 'simd'`; `KernelFactory.create(nodeCapacity, beamCapacity) → SimKernel {kind, state, beams(first, count, events, debugStrains), integrate(first, count, dt, gx, gy, gz)}`; `JS_KERNEL` (beams.ts + integrator.ts), `WASM_KERNEL` / `SIMD_KERNEL` / `bestWasmKernel()` / `simdSupported()` (`src/sim/wasm/kernel.ts`); `defaultKernel()` / `setDefaultKernel(f)`. `EngineConfig.kernel?` (default `defaultKernel()`), `SimEngine.kernel` / `kernelFactory` (helper engines such as the traffic template settle reuse it). The engine calls `kernel.beams` / `kernel.integrate` where it called `applyBeamForces` / `integrateNodes`; nothing else changed in the phase order.
- **SimState may live in WASM linear memory:** `createSimState(nodes, beams, alloc?: StateAllocator)`, `simStateBytes()`, `SimArena(…, state?)`. Each WASM engine owns one fixed-size `WebAssembly.Memory` (never grown: typed-array views never detach); [0, 1 MiB) is the kernel's stack + statics, then the arrays (16-byte aligned, `createSimState` order), then the beam-break list. **Rule for every sim module:** mutate SimState arrays in place, never assign a new array to a SimState field.
- **BIT-IDENTICAL kernels (the determinism contract).** `src/sim/wasm/kernel.c` mirrors `beams.ts` and `integrator.ts` operation for operation (same IEEE ops in the same order, left-associative sums as written in TS, `-ffp-contract=off`, no fast-math, `f64.sqrt` = `Math.sqrt`, forces scattered in ascending beam order one beam at a time; SIMD lanes only compute, any pair with a rare case — non-normal type, inactive, degenerate, past deform / break — is recomputed by the scalar path). Plasticity constants reach C through `set_params` from `beams.ts` (single source of truth). Beam breaks are listed by the kernel in discovery order and emitted by the glue (`events.beamBreak`, same positions). `kernelParity.test.ts` proves it: a fuzzed blob of every beam type driven through yield / lock-up / slack / degenerate / break (every array bit-compared every 100 steps, break events in order) and whole-engine runs (sedan 100 km/h frontal, box truck launch) hash-identical on js / wasm / simd. **Anyone editing `beams.ts` or `integrator.ts` edits `kernel.c` in the same change and runs `tools/build-wasm.sh`** (the parity test fails otherwise).
- **Build:** `tools/build-wasm.sh` (clang 18 + wasm-ld 18, freestanding, `-O3 -nostdlib`, scalar `-mno-simd128` and `-msimd128`) writes `src/sim/wasm/kernel-{scalar,simd}.wasm` and the generated `binary.ts` (both base64), all committed; byte-reproducible (CI installs clang-18 / lld-18, rebuilds and `git diff --exit-code`s).
- **Loading:** the worker imports `./wasm/kernel` LAZILY (its own ≈ 11 kB chunk of the worker bundle; the app chunk is unaffected), installs `bestWasmKernel()` (SIMD → scalar WASM → JS when WebAssembly / SIMD is unavailable or blocked) and queues messages until then. `ReadyMsg.kernel` reports it. Tests: `src/sim/wasm/vitest.setup.ts` installs `CRUMPLE_KERNEL` = simd (default) | wasm | js for every engine a test creates.
- **Replays:** kernels are bit-identical, so `ReplayFile` carries no kernel field and files replay across kernels. Should a future kernel ever not be (a relaxed-SIMD / FMA build), it gets its own `KernelKind`, `ReplayFile` gains `kernel` and `checkReplayFile` refuses files of another kernel.

### Collision triangles (`src/sim/rig/types.ts`; for R-RIG / R-CRASH)
- `RigDef.triangles?: RigTriangleDef[]` — `{a, b, c (node ids of the same rig), material?, twoSided?, thickness?, selfCollide?}`; winding: right-hand normal (b − a) × (c − a) points OUT of the body. One-sided unless `twoSided` (panels, glass: side = where the node was the previous tick). `[]` = no triangles; ABSENT on a vehicle body = derived at compile time by `deriveCollisionTriangles` (`src/sim/rig/triangles.ts`: the beam-lattice triangles (3-cycles) of the body that face open space in the rest pose, oriented outward, one diagonal per quad), so every existing vehicle gets them; a def that declares its own replaces the derivation.
- Node additions: `RigNodeDef.material?` (contact material for the pair law: default the object's — vehicles metal, tread nodes rubber, props `PropDef.material`), `RigNodeDef.selfCollide?` (default = collidable). Compiled: `CompiledRig.triangles?: CompiledTriangles` (`a/b/c` rig-local indices, `flags` `RIG_TRI_FLAG_TWO_SIDED` / `RIG_TRI_FLAG_SELF`, `material`, `thickness`), `CompiledRig.nodeMaterial?` (255 = the object's default), `CompiledRig.nodeSelfCollide?` (1 / 0; absent = collidable). `nodeFlags` values are unchanged.
- **R-RIG's HD variants:** `VehicleVariant.collision` (`CollisionTriangle{a, b, c}`, body node ids, CCW seen from outside = this winding) goes into `def.body.triangles` as `RigTriangleDef`s (generator side; until it does, the quality scaffold copies it there at spawn), so the sheets collide with their own triangles instead of the derived surface.
- A triangle stops colliding once one of its edges has lost all its beams (torn panel); a node never collides with a triangle it is a vertex of, shares a beam with, or touches in the rest pose (self-collision exclusion, computed once per compiled rig).

### Contacts (worker; `src/sim/collision/**`)
- **Node-vs-triangle** between objects (SolverOptions.triangleContact: replaces node-vs-node spheres for object pairs that both have triangles; spheres stay for everything else, e.g. props), **self-collision** (selfCollision) and **static meshes** (`ColliderDef.kind 'mesh'`, `ColliderMesh{positions, indices, twoSided?}` in local space, `size` = local half extents; validated by `resolveColliders`). Broadphase: per-object binned-SAH AABB trees over velocity-fattened triangle boxes, rebuilt with the existing node-vs-node interval; candidate (node, triangle) pairs sorted canonically (lower object id, node index, triangle object id, triangle index). Law: penalty spring on the reduced mass of the node vs the barycentric-weighted triangle point (stability-capped like the sphere law, multi-contact normalized), pair damping, implicit Coulomb friction on the relative tangential velocity, reaction to a / b / c by barycentric weights (momentum exact). Phase: right after node-vs-node (phase 2), canonical order.
- **CCD** (SolverOptions.ccd): speculative contacts — a node that would cross a static face / mesh triangle / another object's triangle within the tick gets a normal impulse limiting its approach to the remaining gap (no tunnelling at 250 km/h into a thin wall or a car side).
- **Material pairs** (`src/sim/collision/contactMaterials.ts`): `contactPair(matA, matB) → {mu, zeta, restitution}` (symmetric table over MaterialId) for node-vs-triangle, node-vs-node and static-mesh contacts; validated by drop (restitution) and slide (μ) tests against textbook values. Metal scrapes keep reporting `skid` events with the struck material (FX turns metal on a hard surface into sparks, unchanged rules). Ground and primitive-collider contacts keep the frozen `node friction × material friction` law (tuned handling / crash results unchanged).
- Penetration (typical depth before → after) is reported in the R-CORE "as built" notes.
